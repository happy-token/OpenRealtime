# 知识、记忆与历史管理

更新日期：2026-10-01。本文描述当前代码的实际行为，适用于维护自己账号下的角色资料。入口为「知识库」和资源库中的「记忆管理」。

## 先确定要管理哪一种数据

| 数据 | 用途 | 管理入口 | 清理后还需要做什么 |
| --- | --- | --- | --- |
| 知识库资料 | 产品规则、FAQ、手册等参考原文 | `/resources?tab=knowledge` | 检查角色启用范围并重新进入对话 |
| 长期记忆 | 偏好、关系、目标、纠正 | `/resources?tab=memory` | 如果当前对话已经提过相同内容，新建对话 |
| 网页对话记录 | 查看已经发生的对话、从有运行时标识的记录续聊 | `/conversations` | 删除记录不自动删除提取出的记忆 |
| 运行时 Journal 与当前上下文 | 多轮推理、工具结果、语义恢复 | 新建对话建立新 thread | 新建不会删除旧网页记录或长期记忆 |

“归零”有不同含义。让助手不再读取长期偏好，用关闭记忆或清空记忆；让下一次聊天不继承当前前文，用新建对话。删除网页历史不等于删除运行时 Journal。当前没有覆盖所有存储和备份的一键账号数据擦除流程。

## 知识库增删改与缩减

1. 在资源库新增资料，可用粘贴文本、文件或公开 HTTPS 网页，无需选择角色。角色关联在角色配置页维护。
2. 点击「预览」查看正文，勾选资料并测试检索；在角色配置中关联同一份资料。
3. 修改时点击「编辑」，改名称和正文并保存。重新导入相同文件名或网页可更新原资料；检查版本号与新正文。
4. 缩减资料可编辑正文，删除失效条款；暂时不用则取消角色绑定并保存，保留原资料供以后维护。
5. 资料列表可直接删除，也可在编辑状态删除；会同步移除所有角色关联，当前没有资料回收站。

共享示例只读，不能当成自己的资料修改。私人资料按账号隔离，可被该账号的多个角色关联。修改资料对所有关联角色生效。并发修改使用 `expectedRevision`：旧版本的修改或删除会返回冲突，刷新后核对新版本再操作，避免覆盖他人的更新。版本号用于冲突检查，当前没有版本历史还原功能。

名称上限 120 字符，正文上限 32,000 UTF-8 字节，上传文件上限 5,000,000 字节；一个角色最多启用 30 份资料。PDF 不支持 OCR。网页不执行脚本，也不能读取登录后的私人页面。检索当前采用关键词片段匹配，语义与向量检索仍是扩展方向。

完整导入、来源和故障排查见[知识库使用指南](/docs/knowledge-base)。

## 长期记忆的维护与重置

在 `/resources?tab=memory` 选择角色，查看数量并点击「刷新记忆」获取其他页面刚保存的记录。切换角色会清除编辑草稿，避免把旧角色的内容误写到新角色。

- **预览**：列表展示完整记忆正文，可搜索内容；展开「预览详情」查看更新时间与手动添加／对话提取来源。
- **增加**：选择个人信息、偏好、关系、目标或纠正，填写内容并添加；每条最多 300 字符，每个账号与角色最多 100 条，相同内容去重。
- **修改**：点击条目「编辑」，修改正文后保存；现有条目的类型和来源不随正文编辑改变。需要不同类型时可删除旧条目再添加。
- **单条删除**：点击删除并确认，适用于失效或冲突信息。
- **重置为零**：点击「清空当前角色记忆」并确认，永久删除当前账号在该角色下的全部长期记忆，不影响其他角色或其他用户。
- **关闭自动使用**：关闭角色记忆开关；不删除记录，停止自动提取和模型注入。关闭期间仍可以手动增加、编辑和删除，便于提前整理。

敏感内容过滤同样适用于手动添加和修改，拒绝包含密码、密钥、手机号、邮箱等内容；这是基于规则的过滤，不能保证识别所有敏感信息。自动提取是保存网页对话记录时的规则匹配，并非模型自动总结。

清空不会关闭自动提取：如果角色仍开启记忆，之后保存匹配句式的对话可能再次产生记录，包括重新保存旧对话。希望保持空白时，先关闭开关，再清空，并从新对话开始。清空不撤回已生成的答案，也不擦除当前会话前文和外部供应商已处理的数据。

运行时构造提示词时读取当前文件，按更新时间选最近 20 条；旧记录缺少时间时保留原相对顺序。更新通常在下一次构造模型输入时生效，已经开始生成的回答不会追溯更新。想验证删除效果，使用新对话，避免前文仍包含同样信息。当前没有记忆回收站、批量导入导出、语义冲突替换或编辑版本冲突保护。

## API 维护约定

以下 API 需要现有登录授权，写入还需要同源检查；记忆和角色关联需要有效角色，独立资料管理不需要角色参数。不要把任意用户 ID 当成授权。API 不提供跨账号管理能力。

| 方法与路径 | 输入 | 结果 |
| --- | --- | --- |
| `GET /api/memory?roleId=…` | 角色 ID | 按更新时间倒序的 `memories` |
| `POST /api/memory?roleId=…` | JSON `{kind, content}` | `201` 与 `memory`，重复内容返回既有条目 |
| `PATCH /api/memory?roleId=…` | JSON `{id, content}` | 修改后的 `memory`；未找到为 `404` |
| `DELETE /api/memory?roleId=…&id=…` | 条目 ID | 删除当前范围中的一条；重复删除也成功 |
| `DELETE /api/memory?roleId=…` | 不传条目 ID | 清空当前账号与角色，幂等 |
| `PATCH /api/knowledge/documents/:id` | JSON `{title,content,expectedRevision}`，`roleId` 可选 | 更新资料，旧版本冲突为 `409` |
| `DELETE /api/knowledge/documents/:id` | JSON `{expectedRevision}`，`roleId` 可选 | 删除资料并清理绑定 |

记忆类型为 `fact`、`preference`、`relationship`、`goal`、`correction`。用户输入不合法返回 `400`，请求过大返回 `413`。记忆文件读取或写入异常返回服务错误；API 授权流程详情以 `conversation-history-auth.ts`、`memory-role.ts` 与知识库授权代码为准。

## 部署、备份与恢复

Next.js 和 Python 必须共享 `KNOWLEDGE_CATALOG_DIR`、`VOICEAGENT_MEMORY_DIR` 和对应角色配置目录。使用绝对路径、持久化卷与同一身份格式；网页看到记录不代表另一个进程读到同一份数据。

当前知识和记忆是文件存储；`VOICEAGENT_STATE_BACKEND=postgres` 只持久化其覆盖的运行时状态，不会自动迁移这些文件。记忆文件是 `memories.json`，知识文件是 `catalog.json`。写入使用锁及临时文件替换，仍需要备份。

备份或恢复时停止所有写入相关目录的进程，保存知识、记忆与角色绑定目录的一致快照，并单独备份 PostgreSQL Journal 及其他资源存储。恢复后核对 JSON 可读、账号隔离、角色绑定、知识检索和记忆开关，再恢复服务。不要直接把运行中的文件替换为空数组，也不要在活跃写入时移除锁。锁恢复步骤见[可靠性运维](RELIABILITY-OPERATIONS.md)。备份包含用户数据，应限制读取权限和保留时间；删除线上条目不会删除旧备份中的副本。

## 建议的验收流程

用测试账号创建两个角色，关联同一份资料并分别添加记忆；验证共享资料更新可被两者读取，解除一个角色关联后停止命中，记忆跨角色和知识跨账号不可见。编辑资料并检索新条款，删除后检查绑定已移除。关闭记忆后手动维护条目，开启后在新会话询问偏好；清空并关闭后新建对话再次验证。对当前有运行时标识的历史验证续聊，并在持久化部署中另做进程重启恢复测试。

单元与接口测试证明存储和隔离规则；实际模型是否检索、如何回答、语音输出和跨进程恢复需要独立验收。更多上下文边界见[Memory 与续聊](/docs/memory-and-history)。

## 工具资源管理

「资源库 → 工具」支持按名称、说明或函数名搜索，以及按启用状态筛选。展开「预览配置」可查看目录中的服务地址、风险、作用及输入 Schema。工具可编辑、启停，并从页面进入「工具权限设置」。内置工具缺省元数据由运行时实现定义；预览目录配置不等于已执行测试调用。状态切换与保存会等待服务端结果，新对话加载最新工具配置。

记忆页面使用单个角色选择列表，只显示该角色的开关和记录。新增与编辑在弹窗中完成。生日目前支持明确自述的数字月份与日期，并兼容 ASR 在月、日之间插入的标点；询问、否认和模糊候选不会保存。不支持的表述仍可能漏提取，请核对记忆列表，模型口头说“记住了”不等于写入成功。
