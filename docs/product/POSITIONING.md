# OpenRealtime 产品定位与差异化

研究更新：2026-10-09。面向全球开源开发者，不以中文应用限定产品范围。以下传播表达为建议；当前能力依据见[证据矩阵](CLAIMS-AND-EVIDENCE.md)，选型依据见[竞品分析](COMPETITIVE-ANALYSIS.md)。

**2026-10-12 最新产品表达：**OpenRealtime 是可自定义、可打断的实时语音交互 Agent。首屏突出自然交流、自由定制、更低成本的服务组合、知识／工具／记忆等丰富功能、现有 Chat Agent 接入，以及可选数字人。产品资料讲解与问答保留为第一个上手示例。[产品概览](../getting-started/OVERVIEW.md) · [配置示例](../getting-started/PRODUCT-ASSISTANT.md)

对外首屏主张：**A real-time voice AI agent you can customize and interrupt. / 一个可自定义、可打断的实时语音交互 Agent。** 面向希望构建自己的助手、扩展已有 Chat Agent 或创建互动角色的使用者。技术栈和会话实现放到开发与部署路径。

成本主张按[成本与灵活性](COST-AND-FLEXIBILITY.md)说明，现有文本 Chat Agent 接入与编码／办事后台的统一任务体验分别见[接入指南](../guides/CHAT-AGENT-INTEGRATION.md)。下文保留历史品牌与技术分析，当前首屏采用本节表达。

## 1. 主张：让自己的 Agent 开口交流，拥有可见的形象

**Bring your AI agents to life with real-time voice and avatars.**

**让你的 AI Agent 通过实时语音和数字人与人交流。**

技术定位：可组合的实时语音与数字人 Agent 运行时。开发者可以独立选择话轮决策、回答模型、声音与数字人呈现，并通过云 API 路线起步，无需自建模型 GPU 推理。

主张面向全球开发者和产品团队；浏览器是当前体验入口。英文 API 接入、英文示例与真实英文对话验收需要补齐，不能把目标市场扩大写成现有多语言能力已全部验证。

## 3. Jev 的传播角色：小决策与复杂回答各司其职

**Jev for turn decisions. Your LLM for answers.**

Jev 在本项目中可回答两类窄问题：用户是否说完，以及插话属于附和、停止、纠正或新请求等哪一类。它返回结构化标签及概率/置信度，运行时据此结合阈值、等待和取消策略执行动作；回答模型继续处理内容生成与复杂推理。

这个故事的吸引力是可以独立选择、观察和调整交互决策。Jev 的文本描述分类范式让当前 adapter 无需训练专属分类模型；跨语言泛化、真实 ASR 噪声下的效果仍需测量。不能从模型定位直接推出本项目更快、更准或端到端低延迟。Jev 是可选 provider，仓库默认配置仍为 llm。

品牌主张围绕 Agent 体验，Jev 适合作为技术传播入口，避免把项目长期价值绑定在一个模型名称上。

## 4. 为什么值得选择，而不仅是另一个语音框架

Pipecat 的优势在成熟的实时语音管线和生态，LiveKit 强于媒体与交付，TEN 覆盖较广的运行时与设备集成，Qwen Audio Agent 与本项目在给 Agent 加语音方面直接重叠。它们也能提供可替换服务、话轮控制或数字人相关能力。

OpenRealtime 的采用理由应是：开发者从已有 Web 体验、具体语义话轮策略和数字人呈现组合出发，保留对回答与交互决策的控制，更快做出自己的可交流 Agent。这是需要用接入步骤、可运行模板和真实 Demo 证明的集成价值，不是已证明的独有能力或性能领先。

最值得积累的优势是可复现的自然交互场景、稳定的组合模板、容易定位的交互故障，以及采用者能完成任务的完整体验。仅添加 provider 名称不足以形成优势。

## 5. 目标采用者与场景

- 全球 Agent 开发者：给已有助手、知识服务或工具型 Agent 增加实时语音和可选数字人入口。
- 小型产品团队：构建讲解、产品导览、互动助手等有形象的对话体验，并自主组合供应商。
- 语音交互工程开发者：独立试验判停、附和与打断策略，观察决策和播放之间的关系。
- 宣传片受众：普通体验者；让其先看到一次真实、有用、可纠正的对话，再引导开发者查看 README。

现有外部 Agent 适配各有能力与配置边界，不宣传任意 Agent/MCP 零代码接入。设备协同和原生 S2S 保留后续方向，当前不作为首发能力。
