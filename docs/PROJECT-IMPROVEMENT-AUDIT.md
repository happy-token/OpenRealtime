## 优先级与验收条件

| 优先级 | 当前情况与证据入口 | 后续工作 | 验收标准 |
| --- | --- | --- | --- |
| P1 保存可靠性 | `src/app/api/conversations/route.ts`、`src/hooks/use-voice-session.ts`；页面排队保存、有 500 条限制 | 退出刷写、分页/分段存储、页面记录与服务端 Journal 对账 | 刷新、关页、网络失败与长对话不静默丢消息，重试不重复 |
| P1 数据擦除 | 记忆、网页历史和 Journal 分开维护 | 定义账号/角色擦除范围，关联知识、记忆、Journal、资源和备份保留策略 | 可验证清理结果；重复执行幂等，不影响其他账号 |
| P1 文件持久化 | `memory-catalog.ts`、`knowledge-catalog-repository.ts` 与 `RELIABILITY-OPERATIONS.md` | 一致快照恢复演练，定义部署副本边界；需要时引入数据库适配器 | 两进程读写一致；重启不丢数据；恢复后绑定和隔离正常 |
| P1 实际恢复验收 | 历史保存 thread/session 标识，默认 Journal 内存 | 在 PostgreSQL 环境验证刷新、进程重启、过期身份、删除角色 | 有权限且历史存在时恢复；不可恢复时明确报错 |
| P1 真实语音质量 | `VOICE-RUNTIME-QUALITY.md` 已定义严格发布证据 | 持续采集真实 ASR/LLM/TTS 的判停、打断和首音延迟证据 | 按既有 SLO 判定；报告提供时间、配置与失败案例 |
| P2 Memory 质量 | 正则提取、最近 20 条、内容去重 | 多事实提取、冲突预览和用户确认、相关性筛选 | 纠正不产生矛盾条目，模型不跨角色引用 |
| P2 并发记忆编辑 | 锁保障文件写入，条目编辑无版本号 | 增加条目 revision 或条件更新 | 两个编辑者修改同条时提示冲突，不静默覆盖 |
| P2 知识维护 | 有 revision，无版本还原和回收站 | 版本对比、回收站、导出与导入预览、来源更新状态 | 能追踪来源和变更、恢复误删、检索不命中过期条款 |
| P2 检索效果 | `server/knowledge_base/local_catalog.py` 使用关键词片段 | 建立问答评测集，再选择混合检索与重排序 | 原词、同义、无答案问题分别报告命中率与错误引用 |
| P2 可观察性 | Memory 自动提取失败不阻止对话保存 | 结构化提取结果、失败计数和管理页状态 | 可区分无匹配、过滤、容量满和存储失败，不记录敏感正文 |
| P2 管理覆盖范围 | Memory 页面通过普通角色列表选择角色；托管数字人 API 有独立 scope | 检查托管数字人与个人角色入口覆盖，并统一资源导航 | 每个可对话主体有明确的知识、记忆管理入口 |
| P3 文档维护 | 存在日期较早的架构与评估报告 | 为状态报告注明快照日期，建立发布文档检查 | 当前指南不把旧限制当成现状，历史报告不覆盖当前状态 |

P1 表示部署和用户数据体验优先项，不代表本次确认出现了数据泄露或运行故障。上述大型功能仍是待办，不能据此宣称项目已完成生产化。当前 CI 已存在 `.github/workflows/ci.yml`，PostgreSQL、身份与并发语音运行时也已有实现；2026-08 的评估文档是历史快照，其中“无 CI/无持久化”等结论不应直接用于现状判断。
