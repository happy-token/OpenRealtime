# PRD：多供应商配置与自定义 Capability Bridge

状态：实施中。本文定义目标与验收口径，不表示当前代码已经支持用户上传并运行 bridge。

## 当前实施进度

- 已建立 ASR／TTS／LLM 内置供应商实例的个人与平台存储、加密凭据、独立选择、编辑、删除与连接测试入口。旧版按供应商保存的 Key 仍保留为兼容路径，未自动迁移或覆盖。
- Bella ASR 已从新增供应商目录和语音服务构建入口移除；旧 Bella ASR 适配器源码和历史测试暂保留，避免在同一迁移中删除无关代码。
- 新语音会话优先读取个人选择，再读取平台默认，最后沿用旧版规则；所选实例 ID 和配置版本固定在准入票据中。已选实例停用时明确拒绝新会话，正在被选择的实例不能直接删除。
- 当前 TTS 实例与角色选择的音色供应商冲突时，新会话明确报错并提示调整，不自动换用另一供应商的默认音色。
- ASR／TTS 和 OpenAI 兼容流式 LLM 的主服务耗时边界已接入现有会话，实例 ID／配置版本在可用时随指标记录。
- 新实例的 LLM 测试会对选定模型发出有界流式请求，验证至少两个非空文本增量并记录首字耗时。ASR/TTS 实例测试已接入受信任 Python 探针：生产部署由 Web 以共享密钥签名请求调用回环地址上的语音服务；本地未配置控制面地址时，以 stdin 向固定内置子进程传递实例 Key。TTS 要求两段文本尚未结束时输出首音，ASR 以平台豆包 TTS 生成固定音频并要求 partial/final；只返回有界的脱敏摘要。测试可能产生少量供应商用量，同一实例 60 秒内不可重复发起，单个所有者每分钟最多 3 次。已使用 `.env` 中的凭据在线验证豆包 TTS 与 ASR 探针通过；当前百炼 TTS 在双流式探针中未于文本流结束前返回音频，判为失败，不能设为当前实例。在线回归用例需显式设置 `RUN_LIVE=1`，默认测试不会产生供应商用量。
- 供应商实例需要相应实时测试通过才能被选用，新会话也会拒绝已选但测试未通过的实例。迁移 `0027` 将旧 ASR/TTS 的“连接通过”记录清为未测试，避免将旧探测误认为完整契约认证；旧版按供应商配置的兼容路径暂不受此约束。
- 新实例的 LLM 流式测试与会话使用同一个 Chat Completions 协议；模型留空时，DeepSeek／OpenAI 使用固定的对应默认模型，不再受旧版平台模型环境变量影响。旧版配置的协议与模型选择保持不变。
- 自定义 bridge 的声明和事件探针已有基础代码，但仓库尚无可验证隔离运行器，用户代码上传、审核、契约测试、部署与运行仍未开放。

## Problem Statement

当前「供应商」页面主要以固定供应商的 API Key 为单位管理。语音识别（ASR）与语音合成（TTS）混在「语音供应商」中；LLM 按最近保存的个人 Key 自动选用；ASR 默认选择主要取决于服务端环境变量。用户无法为同一能力添加多个配置实例、明确切换当前实例，或仅凭一个符合约束的 bridge 接入新供应商。页面的「已配置」也不足以说明相应 ASR、TTS 或 LLM 能力实际可用。

OpenRealtime 已有 `AsrEngine`、`TtsEngine`／流式 TTS、`LlmClient`／工具调用等运行时接口，以及版本化的 Realtime Profile／Plugin Manifest；但这些接口与用户可管理的供应商实例、平台实例、凭据、能力测试和选择关系尚未打通。直接执行用户提交的 Python 代码会带来跨租户数据、平台密钥、文件系统和网络访问风险，不能把它当作普通配置表单处理。

## Solution

将供应商页面按 **ASR、TTS、LLM** 能力组织，并分别展示「平台配置」与「我的配置」。每个能力允许多个实例；用户可添加、编辑、测试、删除自己的实例，并显式选择当前使用的实例。管理员管理平台实例与平台默认值；普通用户只能读取被发布的平台实例的非敏感信息，并可选择它或自己的实例。平台与个人配置互不覆盖。

「新建供应商」提供内置适配器和「自定义 bridge」入口。用户只需提交满足指定版本接口的 bridge 源代码及必要的声明、凭据和模型参数；系统负责静态校验、隔离构建、契约测试、部署与健康检查。用户 bridge 只能在受限 sidecar 中运行，通过统一的 Capability Bridge 协议与应用通信，不得导入到 Web／语音主进程。未能提供强制隔离的部署不得启用用户代码功能。

一个供应商可同时提供多种能力，但配置、测试、选择和运行状态按能力独立；共享凭据采用引用关系，不把「豆包 TTS 测试通过」等同于「豆包 ASR 可用」。实时会话可选的 ASR 必须输出 partial text 和 final text，TTS 必须支持文本输入与音频输出同时流动的双流式模式，LLM 必须流式输出；不满足其中对应契约的实例不能进入实时会话。会话开始时解析并固定选中的实例、bridge 版本和凭据版本；运行中不因配置变化悄悄切换供应商。

## User Stories

1. 作为普通用户，我希望分别查看 ASR、TTS 和 LLM 配置，以便理解每一段对话链路使用什么服务。
2. 作为普通用户，我希望看见平台提供的可选实例与我自己的实例，并清楚区分来源，以便决定使用哪一个。
3. 作为普通用户，我希望同一种能力下保存多个实例，以便在不同账号、模型或端点之间切换。
4. 作为普通用户，我希望同一供应商的 ASR 与 TTS 可以共用凭据但独立选择和测试，以便避免重复录入而不混淆能力。
5. 作为普通用户，我希望通过「新建供应商」下拉列表选择内置供应商或自定义 bridge，以便按能力添加配置。
6. 作为普通用户，我希望新增实例时看到该 bridge 要求的字段、支持的协议和能力，以便填写有效配置。
7. 作为普通用户，我希望编辑实例名称、模型、端点和参数，以便维护多个用途不同的配置。
8. 作为普通用户，我希望更换或清除自己的凭据，而页面始终不回显完整密钥。
9. 作为普通用户，我希望分别测试 ASR 转写、TTS 合成和 LLM 响应，而不是仅验证 Key 或模型列表，以便知道真实能力是否可用。
10. 作为普通用户，我希望看到未配置、未测试、测试中、可用、失败、当前使用、已停用等明确状态及最近测试时间和简短原因。
11. 作为普通用户，我希望测试通过后将实例设为该能力的当前使用配置，以便新会话按我的选择启动。
12. 作为普通用户，我希望删除不再使用的实例，并提前看到对当前选择及进行中会话的影响。
13. 作为普通用户，我希望自定义 bridge 通过标准接口接入未被内置支持的供应商，而不修改平台源码。
14. 作为普通用户，我希望上传 bridge 后先看到校验和隔离测试结果，失败时得到可定位到接口字段或测试步骤的错误。
15. 作为普通用户，我希望 bridge 升级先创建新版本并测试，确认后再用于新会话，以便旧版本仍可回滚。
16. 作为普通用户，我希望明确知道自定义 bridge 能接触哪些对话内容、音频和目标域名，以便作出知情选择。
17. 作为平台管理员，我希望添加多个平台实例、分别测试并指定每项能力的默认实例，以便提供稳定的公共服务。
18. 作为平台管理员，我希望发布或停用平台实例而不暴露平台凭据，以便控制用户可见的选项。
19. 作为平台管理员，我希望为用户 bridge 设定可用语言、依赖、域名、并发、CPU／内存、超时及数据权限上限，以便保护多租户运行环境。
20. 作为平台管理员，我希望审计 bridge 的提交、测试、启用、调用和删除事件，定位滥用或故障时不记录密钥与原始音频。
21. 作为开发者，我希望接入新供应商时只实现相应能力的版本化 bridge 契约和契约测试，而不改会话编排核心。
22. 作为开发者，我希望不同供应商的私有协议、鉴权与响应格式由 bridge 转换为统一事件，以便保持会话引擎稳定。
23. 作为会话用户，我希望当前会话明确显示实际使用的 ASR、LLM、TTS 实例，连接失败时不被静默切到另一家。
24. 作为会话用户，我希望正在进行的会话不会因后台编辑配置而突然更换声音、模型或数据去向。
25. 作为运维人员，我希望 bridge 故障、超时和隔离违规可观察、可停用和可回滚，且不会使整个语音服务进程失效。
26. 作为会话用户，我希望 ASR 在我说话时持续显示 partial text，并在结束时输出 final text，以便及时看到识别进度和最终结果。
27. 作为会话用户，我希望 TTS 一边接收 LLM 的流式文本一边输出音频，以便无需等待整段回复完成才开始播报。
28. 作为会话用户，我希望 LLM 逐步输出文字，而不是等待完整响应，以便更快看到和听到回复。
29. 作为运维人员，我希望分别看到 ASR 首字、ASR 尾包、TTS 首音和 LLM 首字耗时，以便定位语音链路的真正瓶颈。
30. 作为供应商 bridge 开发者，我希望有统一的计时边界和无结果处理规则，以便各供应商指标可以直接比较。

## Implementation Decisions

- **配置模型。** 区分供应商定义、配置实例、凭据、能力绑定和用户／平台选择。实例拥有稳定 ID、能力种类、所属范围与所有者、显示名称、bridge ID／版本、参数版本、启用状态和非敏感测试摘要；同一所有者、同一能力可有多个实例。凭据单独加密存储并通过受限引用供运行时使用，不能作为任意 bridge 的环境变量或完整对象下发。
- **权限。** 平台实例由管理员创建、编辑、测试、发布、停用和删除；普通用户只能管理自己的实例。普通用户可选择已发布的平台实例，不可读取平台凭据或修改平台默认。用户 bridge 和配置对其他用户不可见。所有写入、测试和选择 API 必须验证登录、所属范围和同源请求。
- **选择规则。** 每个用户的 ASR、TTS、LLM 分别保存一个显式选择；没有个人选择时采用对应的已发布平台默认。未配置、已停用、不可解析或不满足必需能力的实例不可用于新会话。选择结果在会话准入时解析为不可变快照，包含实例、bridge、参数和凭据版本；不可静默回退到别的供应商。编辑或删除在用配置不得暗中改变既有会话；删除凭据时应明确终止受影响会话或执行经授权的重配置，而不是继续使用已撤销密钥。
- **能力契约。** 实时 ASR bridge 接收约定的音频帧格式与采样率，必须输出有序、带修订语义的非空 partial text 及每个有语音轮次的 final text，并支持取消和关闭；不得把仅有最终文本的批量转写标记为实时 ASR。实时 TTS bridge 必须实现双流式：在同一合成会话中持续接收文本增量，同时持续输出有序音频块，文本输入尚未结束时即可输出首音；必须支持两侧取消、背压、结束事件与音频格式声明。只有整段文本输入后才流式输出音频的实现不合格。实时 LLM bridge 必须输出有序、非空的流式文本增量，支持取消及有界超时；工具调用事件须有独立类型，不伪装为首字。三类契约分别版本化，不设计一个可任意返回 JSON 的万能回调。批量 ASR 或非双流式 TTS 将来可用于非实时场景，但不能作为本 PRD 的实时会话实例。
- **耗时口径。** 计时点由主服务在统一会话边界记录，使用单调时钟和同一服务端时钟域；bridge 可补充供应商内部耗时，但不能替换下列四项主指标。每项记录会话／轮次、能力实例和 bridge 版本，不记录原始音频、文本或密钥。

  | 指标 | 起点 | 终点 |
  | --- | --- | --- |
  | ASR 首字耗时 | 当前语音轮次的首个语音帧被主服务交付给 ASR | 首个非空 partial text；若 final text 先到，则取首个非空 final text，同时标记缺少 partial 的契约失败 |
  | ASR 尾包耗时 | 当前语音轮次最后一个语音帧被主服务交付给 ASR | 该轮次 final text 被主服务收到 |
  | TTS 首音耗时 | 当前合成轮次首个非空流式文本增量被主服务交付给 TTS | 该轮次首个非空音频块被主服务收到 |
  | LLM 首字耗时 | 当前 LLM 请求由主服务实际发出 | 该请求首个非空文本增量被主服务收到 |

  首／尾帧按同一个语音轮次和统一的帧边界判定，不能把 VAD 停说时间冒充最后一个语音帧；ASR 尾包允许小于首字耗时，但负值属于埋点或顺序错误。空白文本、空音频块、心跳和仅有工具调用的事件不算「首字／首音」。超时、取消、无语音和无文本分别记状态与原因，不伪造 0 ms 或无限大耗时。
- **Bridge 声明。** Manifest 声明能力类型、契约版本、配置 schema、可接触的数据类别、音频格式、目标域名、最大延迟、并发和明确的失败策略。平台可收紧用户声明的权限，用户代码不能自授文件、网络或平台凭据权限。复用现有 Realtime Profile 的能力和数据权限概念；不把 Pipecat 引入为运行时依赖。
- **自定义代码路径。** 第一阶段将 Python 定为候选 bridge 语言以复用现有服务侧接口；最终语言及上传打包格式在隔离运行原型验证后定稿。用户只提交接口实现与声明，不负责部署服务。代码先进入不可执行暂存，完成大小／依赖／静态校验后，由受限构建器生成内容寻址的不可变版本；契约测试在无真实平台密钥的隔离环境运行。只允许显式放行的依赖和网络目标。生产调用在每用户隔离的 sidecar／沙箱中执行，限制 CPU、内存、时长、并发、文件系统和出站网络；无法证明隔离时功能保持关闭。平台内置适配器可沿用受信任运行路径，但必须通过同一能力契约测试。
- **测试与状态。** 「保存」仅代表配置写入；「测试连接」按能力运行有界的最小真实请求并验证完整实时契约，而非只检查 Key／模型列表。测试输出为状态、时间、能力／契约版本、上述对应耗时与脱敏原因，不返回供应商响应体或密钥。修改端点、模型、bridge 版本或凭据后，先前的可用状态失效。TTS 测试可能产生用量，操作前提示；ASR 测试使用获授权的固定测试音频验证 partial 与 final；TTS 测试分多次输入文本并验证输入结束前已有音频；LLM 测试验证多个文本增量，并单独覆盖工具调用能力。是否必须测试通过才能设为当前使用，待验收边界确认；无论如何不可把仅保存的实例标为「可用」。
- **接口资源。** 管理 API 以实例为资源，支持按能力与范围查询、创建、读取、局部更新、删除；测试与激活为实例子操作。bridge 定义／版本有独立只读目录和上传／校验／发布流程。错误返回稳定代码和字段级问题，权限失败、协议不兼容、测试不通过分别表达。列表不包含密钥、源代码或内部路径。所有动态 URL 和出站连接须防 SSRF、重定向与 DNS 回绑定。
- **迁移。** 现有按「用户＋供应商」唯一的个人 Key、按种类唯一的口型服务及环境变量平台配置，迁移为实例模型或通过只读兼容层投影；不覆盖现有密钥、不默默改变当前实际使用的供应商。迁移期间旧页面和新页面必须指向同一事实来源，避免保存成功但会话仍使用旧环境变量。
- **产品布局。** ASR、TTS、LLM 各自显示「当前使用」与平台／个人实例列表；实例卡片呈现供应商、模型、配置状态、最近测试结果和来源，操作统一为测试、编辑、设为当前、删除。新增通过分类下拉列表进入同一配置窗口。数字人及离线模型服务暂保持独立分组，但沿用相同状态语言和设计组件。

## Testing Decisions

- 主要验收接缝是**配置实例保存／测试 → 显式选择 → 新会话准入 → 实际能力调用**，断言用户可观察的提供者、结果和失败行为，而非仅断言某个适配器类被调用。使用现有会话准入、ASR／TTS／LLM 协议及 Realtime Profile 契约测试作为先例。
- API 测试覆盖平台／个人所有权、多个同供应商实例、并发编辑版本冲突、凭据不回显、测试副作用提示、删除当前实例、测试失效与状态排序。跨用户读取、测试或启用必须拒绝。
- 每种能力有提供者无关的契约测试：ASR 必须出现非空 partial 和 final，并覆盖修订、尾帧、断线及取消；TTS 必须在文本流尚未结束时输出首个非空音频块，并覆盖后续文本、音频顺序、背压及双侧取消；LLM 必须流式输出非空文本增量，并覆盖工具调用、超时和取消。内置与用户 bridge 使用同一套可重复测试向量；仅批量响应或模拟流式的 bridge 不能通过实时契约。
- 四项耗时均在上述会话级验收接缝进行端到端埋点测试，使用可控时钟和有序帧／事件验证起止点、轮次关联、重复或空事件、超时、取消及缺失结果；按能力实例报告样本量、P50／P90／P95、错误率与缺失率，不把只完成的成功请求当作全部请求。
- 隔离测试提交恶意 bridge，尝试读取其他租户文件、平台密钥、宿主机环境、内网地址及未批准外部域名；覆盖无限循环、内存耗尽、输出泛滥、进程崩溃、依赖投毒和重定向／DNS 回绑定。验收条件是技术边界阻止访问，不能只依赖代码扫描或提示词。
- 端到端测试以两个用户和至少两个实例验证独立配置、切换、平台默认继承、当前实例标记、测试失败、新旧会话版本固定、删除／停用后的可解释行为；测试账单、原始音频和密钥不泄露到页面或日志。
- 负载与故障演练覆盖 bridge 冷启动、延迟、网络中断、背压、并发上限及容器重启；关键路径不能出现无界等待或无提示的自动切换。

## Out of Scope

- 用任意用户代码直接在 Web／语音主进程内运行、动态 `import` 用户提交模块，或给用户 bridge 主机文件系统、平台密钥、任意网络访问权。
- 仅通过填写任意 URL 自动推断它兼容 ASR、TTS 或 LLM；每个自定义实例必须匹配已声明且验证过的契约。
- 本阶段重写 Turn Policy、Conversation Journal、设备音频协议或数字人渲染链路。
- 在同一进行中的会话里无感热切换供应商；如将来需要，另行定义重配置屏障和用户提示。
- 将 Pipecat 重新引入生产运行时；本产品只借鉴按能力组织供应商的交互方式。
- 公开第三方 bridge 商店、跨用户共享用户代码、收费分成与计费结算。
