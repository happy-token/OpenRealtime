# 角色创建：多模式依赖与动态步骤设计

日期：2026-09-24  
状态：方案 A 已确认并完成首版实现

## 目标

将现有“输入角色名称后立即创建”的流程，改为一个根据呈现模式动态生成配置步骤的角色创建工作台。

角色不一定拥有数字人形象。用户可以创建纯对话角色，也可以为同一个角色同时配置实时、离线和离线加口型等多种呈现模式。页面必须明确展示每个已选模式所需的素材与配置，不得在用户不知情的情况下跳过步骤，也不得创建“模式已启用但依赖素材缺失”的角色。

设计继续沿用当前角色详情页的沉浸式预览、Liquid Glass 配置面板、模块化圆角列表和主页底部模式/动作栏，不复制旧 `/avatars/create` 页面的导航和视觉结构。

## 模式定义

创建页面仅向用户展示以下四种模式：

| 模式 | 内部标识 | 必需资源 | 不需要的资源 |
| --- | --- | --- | --- |
| 对话 | `conversation` | 角色基础配置 | 数字人形象、动作、口型对齐 |
| 实时 | `realtime` | 数字人形象、实时驱动配置与效果确认 | 动作、口型对齐 |
| 离线 | `offline` | 数字人形象、动作底片、与动作配对的口型动作/口型对齐 | 实时驱动 |
| 离线加口型 | `lip-sync` | 数字人形象、动作底片 | 预生成口型对齐、实时驱动 |

“离线”和“离线加口型”的名称容易产生误解，因此界面说明必须直接解释两者的运行方式：

- 离线：使用提前生成并与动作底片配对的口型对齐。
- 离线加口型：使用动作底片，口型在对话运行时生成，不要求提前生成口型对齐。

纯“动作视频”不作为本次角色创建流程中的独立模式。动作是离线与离线加口型的共用素材。如果后续仍需保留内部 `motion` 模式，应单独进行产品确认，不应默认出现在创建页面。

## 角色基础

所有模式都会用到的配置统一放入“角色基础”，不随着模式变化重复出现：

- 角色名称：必填。
- 声音：显示当前供应商、音色和试听入口；允许使用明确展示的默认值。
- 人设 Persona：显示当前选择和一句话简介；允许暂不选择。
- 记忆：开关。
- 工具：显示已选择数量，点击后展开内置、个人、共享工具列表。
- 知识库：显示已选择数量，点击后展开知识库列表。
- 呈现模式：多选，默认只选“对话”。

模型 ID 不在角色创建主流程中展示。它属于高级运行配置，创建时继承系统默认模型，后续如需开放，应放在角色详情的高级配置中，并使用用户可理解的模型名称而不是裸 ID。

角色基础不是一张铺满全部表单的大卡片。它由一组圆角列表按钮组成，每行显示名称、当前选择摘要和进入图标；只有角色名称默认展开，其余配置按需展开。

## 动态步骤模型

选择模式后，通过所选模式依赖的并集生成步骤：

```text
需要数字人形象 = 实时 OR 离线 OR 离线加口型
需要实时驱动     = 实时
需要动作底片     = 离线 OR 离线加口型
需要口型对齐     = 离线
```

步骤顺序为：

```text
角色基础
   ↓
数字人形象（任一数字人模式选中时出现）
   ├── 实时驱动（选中实时时出现）
   └── 动作底片（选中离线或离线加口型时出现）
           ↓
       口型对齐（选中离线时出现）
   ↓
创建确认
```

实时驱动和动作底片在完成数字人形象后是并列任务。两者同时出现时，用户可以任选顺序配置，不必为了完成离线模式先经过实时配置。

## 多模式组合与步骤去重

“对话”不增加任何数字人步骤，因此它与其他模式组合时，只增加一个可用模式，不改变素材依赖。

| 选择的模式 | 动态步骤 |
| --- | --- |
| 对话 | 角色基础 → 创建确认 |
| 实时，或对话 + 实时 | 角色基础 → 数字人形象 → 实时驱动 → 创建确认 |
| 离线，或对话 + 离线 | 角色基础 → 数字人形象 → 动作底片 → 口型对齐 → 创建确认 |
| 离线加口型，或对话 + 离线加口型 | 角色基础 → 数字人形象 → 动作底片 → 创建确认 |
| 实时 + 离线加口型 | 角色基础 → 数字人形象 → 实时驱动 + 动作底片 → 创建确认 |
| 实时 + 离线 | 角色基础 → 数字人形象 → 实时驱动 + 动作底片 → 口型对齐 → 创建确认 |
| 离线 + 离线加口型 | 角色基础 → 数字人形象 → 动作底片 → 口型对齐 → 创建确认 |
| 实时 + 离线 + 离线加口型 | 角色基础 → 数字人形象 → 实时驱动 + 动作底片 → 口型对齐 → 创建确认 |

同一个数字人形象只选择或创建一次，同一个动作底片可以同时服务离线与离线加口型。不得因为选择多个模式而重复上传形象或重复生成动作。

## 步骤内容

### 数字人形象

出现条件：选中实时、离线或离线加口型中的任意一个。

操作：

- 从现有数字人资产中选择。
- 上传正面人物图片并创建新数字人。
- 显示大图预览，保持原始比例并最大化展示，不拉伸。
- 选择已有数字人时，读取其现有的实时绑定、动作和口型对齐，但不静默确认后续步骤。

完成条件：已明确选中一个可用数字人形象。

### 实时驱动

出现条件：选中实时模式。

操作：

- 如果当前形象已有已确认的实时绑定，显示预览和“使用此实时形象”。
- 如果没有绑定，复用旧创建页的实时托管生成、效果预览和确认能力。
- 只有用户确认效果后，步骤才算完成。

完成条件：实时绑定状态为已接受，并由用户确认用于当前角色。

### 动作底片

出现条件：选中离线或离线加口型。

操作：

- 从当前形象的动作资产中选择已有动作。
- 没有合适动作时，进入嵌入式动作创建流程。
- 动作必须经过预览和明确接受，不能由形象图片隐式生成。
- 完成后直接在主页同款底部动作栏中预览。

完成条件：已明确选择一个可用动作底片。

### 口型对齐

出现条件：选中离线模式。

操作：

- 显示当前动作已经配对的口型对齐。
- 允许选择已有素材或生成新的口型动作/口型对齐。
- 新生成素材必须先预览，再确认导入。
- 素材必须与当前动作底片匹配；切换动作后重新验证本步骤。

完成条件：当前动作存在已确认且匹配的口型对齐。

### 创建确认

显示：

- 角色名称、声音、人设。
- 已选择的全部模式。
- 数字人形象、实时绑定、动作底片和口型对齐摘要。
- 工具、知识库和记忆状态。
- 尚未完成的模式及缺失资源。

只有所有已选模式的必需步骤都完成时，才可点击“完成创建”。

## 跳过、取消模式与草稿

步骤能否跳过必须由模式依赖决定，不能使用一个没有语义的通用“跳过”按钮。

- 未选任何数字人模式时，数字人相关步骤不出现。这是纯对话角色的正常流程，不标记为跳过。
- 已选模式的必需步骤不能直接跳过并保留该模式。
- 用户点击“暂不配置此模式”时，应明确展示将被取消的模式，再更新模式选择。
- 跳过数字人形象：取消实时、离线和离线加口型；可保留对话。
- 跳过实时驱动：只取消实时。
- 跳过动作底片：取消离线和离线加口型；可保留实时和对话。
- 跳过口型对齐：只取消离线；可保留离线加口型、实时和对话。
- 草稿允许保存“模式已选择但步骤未完成”的中间状态；正式创建不允许。
- 返回已完成步骤修改资源时，所有依赖它的步骤都要重新验证，不能继续显示为已完成。

创建确认页对未完成步骤提供两个明确选择：“返回配置”或“移除对应模式”，不自动替用户移除。

## 页面共同视觉规则

三种候选方案都遵守以下规则：

- 背景为实时预览舞台：无数字人时使用产品的音频 Orb；有形象时使用图片；有动作或实时预览时使用视频。
- 图片和视频使用 `contain` 逻辑完整显示，背景可使用同源模糊填充，但主体不得裁切或拉伸。
- 底部复用主页的模式与动作组件。未完成的模式可以显示在创建面板中，但不能出现在底部的“可预览模式”中。
- 配置表面使用当前角色详情页的 Liquid Glass 变量、圆角、描边和阴影。
- 不使用顶部 Tab；使用模块列表、任务清单或步骤序列。
- 所有步骤都有“待配置、进行中、已完成、需要重新确认、失败”状态。
- 只在步骤完成、模式被移除或依赖失效时使用过渡动画，避免装饰性动画干扰生成任务。

## 方案 A：动态任务清单（推荐）

### 布局

- 全屏预览舞台。
- 右侧默认 500px、可在 420–640px 间调节宽度的 Liquid Glass 面板。
- 面板顶部显示角色名称、已选模式和整体进度。
- 面板主体是纵向圆角任务模块，一次展开一个；已完成模块折叠显示选择摘要。
- 底部保持主页同款模式与动作栏。

### 交互

用户先完成角色基础并多选模式，页面立即计算任务清单。增减模式时，只增加或移除它独有的步骤，共享步骤保留。点击任意任务可返回修改；依赖步骤会同步重新验证。

### 优点

- 最适合多模式组合，步骤去重关系清楚。
- 符合当前“不要 Tab、统一按钮模块”的方向。
- 不会把旧数字人创建页面的复杂导航带入角色创建。
- 桌面端和移动端都容易转换；移动端可变为底部全高玻璃面板。

### 风险

模式较多时列表会变长，需要依靠折叠摘要控制密度。

### 首版实现说明

- 新建角色入口使用动态任务清单，不再提交名称后直接创建。
- 草稿保存在当前浏览器会话；从形象、动作和口型对齐工具返回时会恢复草稿并识别新增资源。
- 旧 `/avatars/create` 的形象、实时驱动、动作和 Lip Forcing 能力通过 `return_to=role-create` 复用；完成对应素材后返回角色创建工作台。
- 已选模式会写入个人角色记录并在重新读取时保留，不再被形象拥有的全部能力自动覆盖。
- 对话模式始终使用 Orb 预览；只有切换到数字人模式才展示形象或视频。

## 补充设计：角色创建内建素材工作台

### 设计决策

“新建形象、配置实时驱动、新建动作、生成口型对齐”属于角色创建任务，不应继续把用户带到资产管理页面。采用“角色创建主任务页 + 页面内制作窗口”的结构：主任务页负责选择模式、查看依赖和确认结果；制作窗口负责耗时、可预览、可取消的素材生产。

制作窗口不是普通 Dialog，也不是浏览器新窗口。它由 Next.js 拦截路由打开在 `/roles/new` 上方：地址变化、浏览器返回键可关闭、刷新后可恢复为独立页面，但底层角色创建任务和草稿不会因为打开窗口而卸载。每项制作能力仍保留独立 URL：

```text
/roles/new                 角色创建任务清单
/roles/new/avatar          新建数字人形象
/roles/new/realtime        创建并确认实时驱动
/roles/new/action          生成动作底片
/roles/new/talking         生成配对口型对齐 / 口型动作
```

正常点击时这些 URL 显示为覆盖主页面的制作窗口；直接访问或刷新时显示同内容的全页回退版本。最终创建后的角色详情沿用同一组工作台组件，并替换 `new` 为角色 ID。这样角色创建和角色修改共享制作体验，不再依赖 `/avatars/create`、`/services/motion` 和 `/services/talking` 的页面结构。

不使用真正的浏览器新标签页或新窗口：它们会带来弹窗拦截、移动端不一致、多个草稿副本和返回状态难同步等问题。

### 共同页面框架

制作窗口统一复用 `RoleCreationWorkbenchShell`：

```text
┌──────────────────────────────────────────────────────────────────┐
│ ← 返回创建任务   创建角色 · 2/5                 保存草稿   帮助 │
├───────────────────────────────────────┬──────────────────────────┤
│                                       │ 当前任务                 │
│                                       │ 新建数字人形象           │
│          完整比例预览舞台             │                          │
│     图片 / 动作 / 讲话效果对比         │ ○ 素材来源               │
│                                       │ ○ 参数与质量检查         │
│                                       │ ○ 生成或上传             │
│                                       │ ○ 预览并确认             │
│                                       │                          │
│                                       │ [保存并继续]             │
├───────────────────────────────────────┴──────────────────────────┤
│ 对话  实时  离线  离线加口型     当前形象 / 动作 / 任务状态      │
└──────────────────────────────────────────────────────────────────┘
```

- 左侧继续使用沉浸式预览舞台；主体媒体 `contain` 完整显示，使用同源模糊背景填充空白。
- 右侧是 500px、可调宽度的 Liquid Glass 制作面板。
- 桌面端窗口默认占可用区域约 92% × 88%，居中显示，可调节大小并支持一键最大化；不默认自由拖动，避免主要操作区位置漂移。
- 主任务页保留在窗口下方，以暗化和轻微模糊处理，让用户始终知道仍在创建同一个角色。
- 同一时间只打开一个制作窗口，不允许形象、动作和口型对齐窗口层叠。
- 移动端自动切换为全屏页面，不模拟桌面浮窗。
- 不使用 Tab。素材来源、参数、生成状态和确认结果使用纵向圆角模块，一次展开一个。
- 顶部始终显示“创建角色”上下文、任务序号和返回任务清单，不出现“资产管理”导航。
- 底部保留角色创建的模式状态；制作中不可切换到会破坏当前任务的资源。
- 离开页面不会取消服务端生成任务；再次进入时根据任务 ID 恢复进度。
- 生成已经提交后，“关闭”变为“收起”；任务以创建页上的状态胶囊继续显示，完成时更新对应任务模块。

Next.js 路由结构使用 Parallel Routes 与 Intercepting Routes：

```text
app/roles/new/layout.tsx                 共享角色草稿 Provider
app/roles/new/page.tsx                   创建任务主页面
app/roles/new/@studio/default.tsx        未打开制作窗口
app/roles/new/@studio/(.)avatar/page.tsx 浮层形象制作窗口
app/roles/new/avatar/page.tsx            刷新/直达的全页回退
```

实时、动作和口型对齐采用相同结构。这样“看起来是一个新窗口”，但状态、历史记录和可访问性仍由应用统一管理。

### 新建数字人形象页

父任务页负责选择已有形象；只有点击“新建形象”才进入本页，避免“选择已有”和“创建新资源”混在一起。

右侧模块：

1. **形象来源**：上传图片、AI 生成。内部预置形象仍属于已有形象选择，不放入“新建”页。
2. **图片预览与检查**：显示分辨率、宽高比、人脸可见性和文件大小；问题只给出具体修正建议。
3. **形象名称**：默认继承角色名称并允许修改。
4. **模式兼容性**：根据已选模式说明后续还需实时驱动或动作，不在此处自动生成。
5. **创建确认**：保存为用户形象并直接写回当前角色草稿。

创建成功后提供两个动作：

- 主按钮“保存并继续”：进入当前任务清单中下一个未完成步骤。
- 次按钮“返回创建任务”：回到 `/roles/new` 查看整体状态。

如果同时选择实时和离线模式，下一个步骤按“实时驱动 → 动作底片 → 口型对齐”的默认顺序推荐，但用户可以返回任务清单改用其他顺序。

### 实时驱动页

- 左侧先显示原始形象，生成后切换为实时预览视频。
- 右侧仅展示当前可用的实时供应商、名称和必要参数；供应商 API Key 缺失时在当前页完成配置。
- 创建候选结果后必须进入“效果确认”状态；用户点击“确认用于角色”后才写回草稿。
- 拒绝候选不会删除形象，只清理本次候选绑定。
- 实时模式不出现动作、口型或口型对齐配置。

### 动作底片页

- 当前数字人形象固定显示在页面顶部，避免为错误形象生成素材。
- 素材来源按按钮模块展开：动作模板驱动、上传参考视频、AI 视频生成。
- 模型和供应商属于“高级设置”，默认折叠；主界面展示时长、画幅、预计费用和授权要求。
- 生成开始后，右侧模块切换为任务进度，左侧仍保留形象和结果预览。
- 生成完成后先预览，再点击“保存为动作底片”；未经确认的候选不进入角色草稿。
- 已保存的动作立即出现在角色创建底部动作栏，并可同时供离线和离线加口型模式使用。

### 口型对齐与口型动作页

本页只在已经选定动作底片后进入。顶部固定展示“当前形象 + 当前动作”，切换动作需要回到任务清单，避免生成结果与源底片错配。

生成方式使用列表按钮，不使用供应商 Tab：

| 方式 | 页面说明 | 必要输入 |
| --- | --- | --- |
| Lip Forcing | 为离线模式生成与动作配对的预生成口型对齐 | 角色声音或可选参考音频 |
| MuseTalk | 本地 GPU 口型动作 | 当前动作底片 |
| Wav2Lip | 离线口型，受非商业许可约束 | 参考音频、素材权利确认 |
| MiniMax | 基于视频参考生成讲话版 | 时长、提示词、个人 API Key 与费用确认 |

每种方式显示“可用状态、用途、是否收费、是否已有配对素材”。生成完成后左侧提供“原动作 / 讲话效果”切换预览，必须确认导入后才成为当前角色的口型对齐。

“离线加口型”模式只要求动作底片，不强制进入本页；本页生成的是可复用的预生成口型对齐，主要用于“离线”模式。

### 数据与组件边界

流程内创建不等于角色私有素材。形象、动作和口型对齐仍保存到当前用户的资源目录，角色草稿只保存资源 ID：

```text
角色草稿 ──选择──> 数字人形象 ──包含──> 动作底片 ──包含──> 口型对齐
```

这样同一形象和动作可以被多个角色复用，也不会因为以后删除旧资产管理页面而迁移数据。需要剥离的是旧页面和导航，不是底层资源模型与生成 API。

组件分层：

- `RoleCreationWorkbenchShell`：创建上下文、预览舞台、玻璃面板、底部模式栏。
- `AvatarSourceComposer`：上传、AI 生成、图片检查和形象保存。
- `RealtimeBindingComposer`：候选生成、预览和接受。
- `ActionComposer`：动作来源、参数、生成任务、预览和接受。
- `TalkingMaterialComposer`：方式选择、参考输入、任务恢复、预览和接受。

现有 `AvatarStudio`、`AvatarActionStudio`、`AvatarLightweightConfig` 中的请求和任务恢复逻辑逐步下沉到这些 Composer；旧页面在迁移期调用同一 Composer，避免新旧两套生成逻辑并行维护。

### 草稿与长任务

首阶段可以继续用 `sessionStorage` 保存角色基础选择，但生成任务不能只依赖页面内状态。每次提交生成都要保存：

- 创建草稿 ID。
- 任务类型、供应商和幂等请求 ID。
- 源形象、源动作和源视频版本。
- 服务端任务 ID、进度和候选结果。
- 用户是否已经确认导入。

完整迁移阶段增加服务端角色草稿，使刷新、重新登录和跨设备恢复成为可能。任何收费生成遇到未知提交状态时不得自动重试，必须恢复原任务或提示用户确认。

### 分阶段迁移

#### 阶段 1：新建形象页

- 新增 `/roles/new/avatar`，替换创建任务里的 `/avatars/create` 跳转。
- 复用现有个人形象上传 API，完成后直接更新角色草稿。
- `/avatars/create` 保留，资产管理中的旧入口暂不修改。

#### 阶段 2：实时驱动与动作页

- 新增 `/roles/new/realtime` 和 `/roles/new/action`。
- 把 `AvatarStudio` 的实时逻辑与 `AvatarActionStudio` 的动作逻辑拆成可复用 Composer。
- 创建角色和角色详情首先切换到新页面；旧资产页面继续兼容调用。

#### 阶段 3：口型对齐页

- 新增 `/roles/new/talking`，统一 Lip Forcing、MuseTalk、Wav2Lip 与 MiniMax。
- 替换 `/services/talking` 和旧轻量动作页面在角色流程中的入口。
- 验证任务恢复、源动作版本匹配和预览后确认流程。

#### 阶段 4：移除旧创建页面

- 全站搜索并替换 `/avatars/create`、`/services/motion`、`/services/talking` 的业务入口。
- 资源页面只保留浏览、搜索、删除、分享和复用，不再承担角色创建向导。
- 观察一个版本周期后移除旧页面路由；期间保留跳转到新角色工作台的兼容重定向。

### 验收条件

- 从创建角色开始，用户无需进入任何资产管理页面即可完成四种模式的所有必要配置。
- 返回任务清单后，新建资源已自动选中，其他已完成配置不丢失。
- 生成过程中刷新页面不会重复提交任务或重复计费。
- 切换形象或动作后，下游实时、动作和口型对齐状态会立即重新验证。
- 所有候选素材必须先预览并确认，不能因为任务成功而自动绑定角色。
- 旧资产页面仍可在迁移期独立使用，并与新页面读写同一套资源数据。

## 方案 B：模式路线图

### 布局

- 左侧或中部是预览舞台。
- 右侧较宽的玻璃面板先显示“共同基础”，下方按已选模式显示多条路线。
- 每条路线显示自己的依赖链，例如“离线：形象 → 动作 → 口型对齐”。
- 被多条路线共用的节点只创建一次，通过连线或“被 2 个模式使用”标签关联。

### 优点

- 用户最容易理解每个模式为什么需要这些步骤。
- 对模式依赖和共享资源的解释最直观。
- 适合后续增加更多模式或供应商能力。

### 风险

- 视觉信息量最大，窄屏适配较困难。
- 路线与共享节点的连线容易使界面更像流程编辑器，弱化角色预览。
- 实现和测试成本高于方案 A。

## 方案 C：生成式分步向导

### 布局

- 保留全屏预览。
- 右侧面板一次只展示一个步骤。
- 顶部显示由当前模式组合动态生成的步骤序列和完成数量。
- 上一步、下一步和保存草稿固定在面板底部。

### 优点

- 单屏内容最少，新用户最容易聚焦。
- 小屏幕体验最好。
- 可以直接嵌入现有数字人创建能力。

### 风险

- 用户不容易同时看见多模式之间共享了哪些步骤。
- 返回修改较慢。
- 容易再次产生“系统替我跳过了什么”的疑惑，必须额外提供完整流程概览。

## 方案比较

| 维度 | 方案 A：动态任务清单 | 方案 B：模式路线图 | 方案 C：分步向导 |
| --- | --- | --- | --- |
| 多模式组合 | 最好 | 最直观 | 一般 |
| 步骤透明度 | 高 | 最高 | 中等 |
| 页面简洁度 | 高 | 中等 | 最高 |
| 与当前角色详情风格一致性 | 最高 | 中等 | 高 |
| 移动端适配 | 好 | 较难 | 最好 |
| 实现复杂度 | 中等 | 高 | 较低 |
| 后续维护 | 好 | 中等 | 好 |

## 推荐结论

推荐方案 A“动态任务清单”。它能在不使用 Tab 的前提下，把多模式依赖、步骤去重、已有素材复用和明确的完成状态放在同一个页面中，也最容易复用当前角色详情页、主页预览与旧数字人创建页的现有能力。

建议首版按以下范围实施：

1. 角色基础与四种模式多选。
2. 根据模式生成形象、实时驱动、动作和口型对齐任务。
3. 支持选择已有素材和进入嵌入式创建流程。
4. 复用主页预览舞台及底部模式/动作栏。
5. 支持草稿与依赖重新验证。
6. 完成前进行模式可用性校验，不允许保存无效组合。

旧 `/avatars/create` 可以继续作为独立的数字人资产创建入口；角色创建只复用它的能力组件和数据操作，不复用旧页面壳，也不通过跳转后猜测新增资源来完成角色绑定。
