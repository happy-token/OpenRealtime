# 在数字人资产页管理口型对齐

## 目标与位置

口型对齐是某个 Avatar 动作底片的配对版本，不是另一个独立动作。在 `/avatars` 资产卡片上始终显示「口型对齐」悬浮按钮，点击后展开卡片并在预览左侧打开可滚动浮层，列出当前动作底片、各讲话版、删除与恢复入口；预览播放所选素材。浮层关闭后保持当前预览，切换动作时列表同步切换。`/avatars/{avatar_id}` 详情页也保留原有管理区。无讲话版的动作在浮层中显示空状态和「生成口型对齐」入口。内置但不属于当前账户的动作只提供查看，不提供删除。

## 页面交互

```
资产卡片 [口型对齐] → 打开浮层
┌ 当前动作：柔和回应 ┐ ┌─────────────────────┐
│ ○ 动作底片         │ │                     │
│ ● MuseTalk 1.5 [删]│ │   当前素材视频预览    │
│ ○ Lip Forcing  [删]│ │                     │
│ 已删除素材 1 [展开] │ └─────────────────────┘
│ [生成口型对齐]      │
└────────────────────┘
```

- 左侧行显示生成方式和素材名称，点击后在右侧按原比例播放；每行有独立删除按钮。选择预览不改变会话选择。
- 删除前显示具体素材与所属动作，并说明它会立即离开新会话选择、30 天内可恢复；删除动作底片的按钮与删除某一讲话版的按钮分开。
- 成功后当前动作、其他讲话版和源视频仍在；该行进入本动作的「已删除口型对齐」。恢复时保留原 ID 和视频。生成入口指向 `/avatars/create?task=lightweight&avatar_id=...&avatar_action_id=...`，创建页预选对应底片。
- 无效配对（`source_video_url` 与动作现有 `video_url` 不同）显示为「底片已变更」，不可用于会话，但允许预览和删除。避免静默把旧讲话版配到新底片。

## 数据与接口

- 给 `AvatarTalkingVariant` 增加 `deleted_at: string | null`；旧数据缺少字段时视为未删除。现有动作软删除保留 30 天，此处沿用同一周期。
- 新增 `PATCH /api/avatars/{avatarId}/actions/{avatarActionId}/talking-variants/{variantId}`，只接受 `{ "operation": "trash" | "restore" }`。沿用资产写接口的权限检查和同源校验。服务端在目录锁内校验数字人、动作、讲话版的从属关系，并原子更新目录；重复删除或恢复返回当前状态。
- 会话选择器、配对解析、生成复用检查、创建页预览均只使用未删除且匹配现有底片的讲话版。已保存的会话选择若指向被删 ID，启动前要求重新选择；运行中的会话应停止使用该讲话版并回到明确的可用状态，不能继续引用已撤销素材。
- 同一动作和生成方式只允许一个未删除版本。生成新版本时旧版自动移入已删除列表；恢复与后来生成的同方式版本冲突时返回 `409`，由用户先决定保留哪一个；生成中的任务若被撤销，完成后不能重新挂回已删除记录。
- 30 天到期后清除记录，并且仅在没有其他记录引用文件时清理 `public/digital-human/talking-variants/{id}.mp4`。文件清理由受约束的素材 ID 构造路径；供应商远端文件不随本地删除承诺清理。

## MiniMax 结果入库

MuseTalk 与 Lip Forcing 等已保存的 `talking_variants` 可直接进入上述列表。MiniMax 生成结果通过受信任任务记录与当前动作底片哈希校验后，复制到数字人拥有的本地存储并登记为 `talking_variant`。如果入库失败，浏览器草稿保留预览与任务恢复信息，但资产页不会将它显示为已保存素材。

## 验收

1. 两个讲话版共用同一动作时，删除一个不影响底片、另一个讲话版或其他动作。
2. 删除后刷新资产页、创建页和会话配置，已删除版只出现在本动作的可恢复列表；已有会话选择不能重新启动它。
3. 30 天内恢复保留原 ID 和视频；与新的同方式版本冲突时给出清晰提示。
4. 非所属动作、内置只读动作及未授权请求不能删除；删除与生成同时发生时不会让已删素材复活。

当前资产目录沿用项目现有的管理员或测试会话权限模型，尚未为每个数字人记录独立账户所有者；多账户隔离需随资产目录权限改造完成。
