# 数字角色长期方向与当前数字人优先级

日期：2026-09-11。用户认可记录为产品方向；当前仍聚焦真人数字人的交互画质，尚未决定切换到 3D。

## 当前优先级

改善现有数字人的口型、脸部自然度、动作连续性与实时交互。使用用户提供的 `ssh dev` GPU 服务器，以“柔和回应”原始动作和固定音频对比新口型模型。优先验证 MuseTalk 1.5，Wav2Lip 作为既有基线。GPU 加速与模型画质是两个变量；离线视频成功不代表实时首帧、稳定吞吐或打断已验证。

## 长期产品方向

目标是用数字角色展现语音交互能力，提供情绪价值，以娱乐、自由度和开发兴趣为核心。角色需要开箱有趣，再逐步开放改造能力。

参考 Microduck 的即时可玩与行为分享理念，但保留本产品的自然语言交互优势。单纯“角色加聊天”不足以构成差异化，重点探索：

1. 即兴小剧场：语音进入情境，随时插话改变剧情，角色同步调整声音、表情与动作。
2. 教角色新反应：用自然语言定义触发条件、动作、台词与场景变化，预览、保存、立即试用。
3. 共同操作场景物件：注视、触碰、评论与记忆围绕共同对象展开。

招牌体验候选：“用说话的方式，教会角色一个新玩法”。普通用户能够直接组合行为，开发者能够编辑事件、动画、声音与工具接口并分享作品。

## 表演层设想

在对话与渲染之间增加统一表演意图，协调语气、注视、表情、姿态、动作。区分本地即时反应、模型语义反应和逐帧动画。事件沿用 generation / speechId，按实际音频播放时间调度；打断时停止声音、收嘴、取消未来动作并过渡到倾听。处理部位控制冲突、优先级、持续时间、退出方式和重复冷却。

风格化 3D / VRM 是未来验证候选，真人渲染可作为另一外观后端。预生成视频适合登场、庆祝、短舞蹈等，持续交互需要及时响应。当前不据此改动产品主线。

## 验证方式

先比较当前真人优化版、新真人渲染后端与精心设计的风格化角色小样。除口型、延迟和连续性，还看主动多玩一轮、教新行为和分享的意愿。200ms 即时视觉响应和打断停声可作为待实测目标，不能视为现有承诺。
