## 1. 目标与已确认约束

优先缩短两段用户体验延迟：

- 用户最后有效语音结束 → 对应回复在客户端实际开始播放。
- 用户有效打断语音开始 → 对应旧回复在客户端实际停止播放。

已确认的设计约束：

1. 判停、打断继续采用独立的 JEV 分类任务，当前配置模型为 `jev-1.13.0`。明确控制指令允许规则快速处理。
2. 不逐字发送累计 partial，不随着每次 ASR 文本更新取消、重发模型请求。
3. 采用独立文本 chunk；标点作为主要切分依据，结合文本稳定性、停说证据和兜底边界。
4. 打断没有标点时，累计 **5 个有效字**触发一次判断，阈值可配置。只统计尚未发送的新文字。
5. 打断链路不增加语义判停；确认有效打断后可以立即停止旧输出，不等新任务说完。
6. 标点、字数负责决定何时请求，不直接决定停说或停播。
7. 请求、结果、播放动作必须绑定 Session、轮次、chunk 和目标回复，不能让迟到结果停止新回复。

本计划不要求更换回复 LLM，不以模块耗时相加代替整体体验延迟。录音存储、Agent 专用凭据等后台功能另行规划。

## 3. 文本 chunk 合约

### 3.1 切分策略

普通判停与打断共用切分基础设施，使用不同策略：

| 场景 | 主要边界 | 无标点兜底 | 动作约束 |
| --- | --- | --- | --- |
| 普通判停 | 稳定的句号、问号、感叹号；逗号、分号形成候选短段 | 停说后封尾段；长段设置可配置长度/时长上限 | complete 只提供语义证据，真正提交还需停说及版本一致性 |
| 语义打断 | 稳定标点；明确停播规则优先 | 尚未发送的文字达到 5 个有效字；停说时封不足 5 字的尾段 | 有效打断结果可以立即停旧输出，不调用 EOT |

有效字计数不包含空白、标点。首版按中文有效字符计数；英文单词、数字和混合文本增加独立测试，不把中文 5 字机械当成英文 5 个字母。句点还要排除小数、网址等非分句用途。

标点出现先形成候选边界，不把“末尾出现一个标点”当作 ASR 已确认稳定。优先使用提供者稳定分句信息；没有明确稳定信息时采用可配置的短稳定窗口，并测量它增加的等待。首版窗口值由基线回放确定，不在本计划中作为已生效配置。

### 3.2 标识与文本版本

chunk 至少携带：

- Session ID、generation、turn_id、chunk_id、chunk_version。
- 当前 chunk 文本、源 revision 范围、文本起止位置。
- 触发原因：punctuation / character_threshold / speech_stop / upper_bound / explicit_control。
- 候选形成、封口、入队、发出时间。
- 可获得的音频起止时间、ASR 稳定性；未知值明确标记 unknown。
- 打断时的 target_response_id、当前助手已播放内容及必要的短上下文。

每个已发出的 chunk 版本只请求一次。ASR 的 `delta` 在替换情形可能是完整修订文本，不能直接追加为“新增 chunk”。切分层依据累计文本和 revision 投影未发送范围。

已封口范围若被 ASR 实质修订，显式使旧版本失效，必要时产生 correction 版本；这是例外修订，不是每个 partial 都重发。纯标点变化不得重发相同语义文本。日志保留修订原因。

### 3.3 跨 chunk 语义

主要判断输入是独立 chunk，附带有界的必要上下文，不每次重发整个累计用户表达或完整历史。

例子：

- “帮我查天气，明天上海会下雨吗？”：按边界形成新块，第二块保留前一块的必要语境。
- “如果明天下雨，”：可以封候选块，但不能因逗号直接提交轮次。
- “我不是要你停下来”：不得因截出的“停下来”片段直接停播。
- “我想订一张” / “明天去上海的票”：结合短上下文判断，不将独立请求理解为丢弃语境。

先冻结短上下文大小和序列化字段，再用跨块否定、纠正、省略样本校准。不能通过简单删除全部上下文换取低延迟。

## 4. 请求调度与结果取舍

首版按会话、按任务类别限制一个模型请求在途。判停和打断互斥于当前输入路径，不通过多发请求掩盖远端延迟。

调度要求：

1. ASR 更新先入缓冲；只有 chunk 封口才申请请求。
2. 在途请求不因普通新增文字而取消。等待期间积累尚未发出的候选内容。
3. 队列有上限、有等待期限。超载时可以将尚未发出的相邻候选合成一个新 chunk，保留其来源范围；不能无界排队或静默丢弃最终表达。
4. 已发出 chunk 的 ID、版本、文本保持固定。新 chunk 不复用旧请求 token。
5. 同内容去重；sentence end、VAD 停说和标点若对应同一已发出内容，不重复调用。
6. Session 结束、目标回复失效、ASR 实质修订等生命周期变化可以取消请求，取消原因入日志。
7. 明确停播指令不被模型队列阻塞；规则需要考虑否定表达和已有回声过滤。

结果不是“谁最后回来就采用谁”：

- 核对 chunk 版本、轮次、目标回复和输入修订状态。
- 判停结果只有与待提交表达一致时才能用于提交；旧块的 complete 不能结束后来仍在补充的表达。
- 打断结果仍需核对目标回复及后续纠正信息；过期或冲突结果丢弃并记录原因，不能停止替换后的回复。
- 不确定结果保留输入，等待下一块或停说证据；不把超时当作有效打断。
- 停旧输出与提交新用户轮次分别管理：前者可以早发生，后者仍需输入结束证据。

首版不盲目降低 0.8 判定阈值或附和抑制阈值。请求总量、合并上限和队列等待期限在回放基线中确定，支持配置与灰度回退。

## 5. 实施顺序

### 阶段 0：测量基线

保持现有逻辑，补观测并保存固定回放集。记录 ASR 文本/标点到达、请求取消、连接与排队、JEV 结果、停播指令、首播/停播时间。

覆盖普通短句、长句无标点、犹豫停顿、地点纠正、明确停止、附和、背景音/回声、连续打断、ASR 改写、回复切换。合成回放与真实麦克风测试分别报告。

交付：可复跑数据集、旧逻辑指标、延迟构成和请求次数基线。

### 阶段 1：chunk 与打断快路径（最高优先级）

新增纯文本 chunk 切分模块，接入 ASR 版本与边界；协调器用 chunk 请求替代按累计 revision 重发。实现标点边界、无标点 5 字、尾段封口、去重、纠正版本及有界调度。

关联文件：`asr.py`、`doubao_asr.py`、`coordinated_turn_manager.py`、`semantic_input.py`、`jev_classifier.py`。新切分模块放在语义输入层，避免供应商 SDK 承担轮次决策。

交付：请求可追溯、不逐字请求、不重复取消；打断持续跳过 EOT。

### 阶段 2：连接复用与停播优先（最高优先级）

- 给 JEV 客户端明确创建、共享、并发限制和关闭契约，复用 HTTP 连接。
- 单次超时覆盖排队与网络；取消单次请求不关闭仍被其它任务使用的共享客户端。
- 连接失效能够恢复，实时路径不引入隐式自动重试风暴。
- 打断确认后优先发送旧输出的停播指令，再后台取消/清理 LLM、TTS 和工具任务。
- 浏览器音频立即清掉旧 generation 的计划播放和缓冲；迟到旧音频拒收。
- 数字人输出需要验证播放器真正停止的确认。调用 cancel 方法不能直接冒充实际停播；不支持确认的 renderer 标记缺失/代理值。

关联文件：`jev_classifier.py`、`runtime.py`、`voice_web_server.py`、`cascaded/engine.py`、`transport/websocket.py`、`use-voice-session.ts`、浏览器/数字人音频桥接。

交付：共享客户端生命周期回归、停播不依赖模型清理、各 renderer 的能力说明。

### 阶段 3：接通回复预生成（次高优先级）

新协调器显式调用已有 prepare/invalidate：只在稳定、有望提交的表达上预生成，不在每个 5 字打断 chunk 上生成回复。

- 首版只提前 LLM，确认轮次后才交付播放。
- ASR 实质修订、用户继续补充、打断/目标回复切换、会话结束时失效。
- 仅使用与最终提交内容匹配的缓存，确保不会产生重复请求或重复输出。
- 检索/工具依赖未确定时不提前执行有副作用工具；只读准备需明确边界。
- 分别统计命中、丢弃、重复请求和首播收益。
- 之后再评估提前 TTS，保留独立开关。

关联文件：`coordinated_turn_manager.py`、`speculative_brain.py`、`speculative_speech.py`。

### 阶段 4：细调与可选方案

依据实测调整短稳定窗口、ASR endpoint、VAD、尾包等待及短上下文大小。核查并行等待，避免重复增加静音窗口。若连接与调度优化后远端 JEV 仍占主导，再对照评估本地轻量分类器或音频判停模型；此项不是本轮默认替换决策。

## 6. 日志与看板

增加可按 Session / turn / chunk / request / response 查询的关联信息：

| 指标 | 测量边界 |
| --- | --- |
| chunk 成形等待 | 对应文本首次可见 → chunk 封口 |
| 分类排队 | 入队 → 请求获得执行资格 |
| JEV 请求耗时 | 发出请求 → 完整决策返回，包含网络 |
| 连接耗时 | 可观测的连接建立阶段；无法获得时不造数 |
| 决策到停播指令 | 有效结果被接受 → 停播指令发出 |
| 客户端停播处理 | 客户端收到指令 → 实际停止旧输出 |
| 整体打断 | 有效用户开口 → 旧输出实际停止 |
| 整体回复 | 用户最后有效语音结束 → 客户端实际首播 |

客户端与服务端的独立单调时钟不能直接相减。设计音频时间轴、时钟映射及误差说明；服务端回执往返只作为明确命名的代理指标。记录 chunk 触发原因、模型标签/置信度、规则命中、结果采用/丢弃原因、取消原因、待发合并范围、预生成命中/失效。

看板同时展示 P50/P95/P99、样本数、缺失比例、每轮请求数及误打断/漏打断率。采集丢弃或写入异常时，不将部分样本当作完整结论。

## 7. 回归与验收

自动测试必须覆盖：

- 逐字 ASR 更新不会逐字调用模型；标点重写及重复 sentence end 不重复请求。
- 无标点达到 5 字发出一次，下一请求只包含未发送内容；不足 5 字停说封尾段。
- 标点候选稳定、否定跨块、小数/网址、中文/英文混合、ASR 替换与版本失效。
- 后续文字不取消有效在途请求；排队有界且最终输入不丢失。
- 迟到结果、回复 A→B 切换、连续打断、会话关闭均不会污染新轮次。
- 打断路径 EOT 调用数始终为零；普通判停 complete 不截断仍在说话的用户。
- 规则停播不被模型队列阻塞；未知/超时不伪装为成功分类。
- 模型任务不配合取消时，客户端仍能及时停止旧输出。
- 浏览器及启用的数字人播放器拒收迟到旧音频，区分请求停止和实际停止。
- 连接复用、并发取消、恢复与关闭无泄漏；预生成缓存只匹配正确最终输入。

性能验收分两部分：

1. **确定性行为验收**：上述规则全部通过，日志能够解释每个请求和动作，采集无未说明缺口。
2. **实测效果验收**：同一回放集与相同环境，对比请求数、整体延迟及准确率。每类报告样本量与异常；没有足够样本不报告可靠 P99。

初步性能目标：整体首播/停播 P95 相对基线改善至少 20%，误打断和提前截断率不恶化；这是待基线确认的工程目标，不是承诺已达到。短明确停播指令单独衡量规则路径，不混入远端模型样本。5 字阈值与客户端处理耗时也不保证整体打断小于固定毫秒数。

## 8. 灰度与回退

chunk 调度、共享连接、停播优先、LLM 预生成、提前 TTS 分别提供开关与配置版本。按阶段启用，保留旧路径用于同条件对照；影子分类只采集结果、不执行停播，也要计入请求预算。

发现误打断、输入丢失、串轮、资源泄漏或日志缺口时，关闭对应阶段，保留复现 Session 和配置版本。回退不能改变当前会话的标识和授权边界。

## 10. 第一批实施记录（2026-10-04）

已实现并接入 `voice_web_server`：

- 普通判停按稳定标点切块，停说时封尾段；无标点长输入使用 64 个有效单位上限。
- 打断无标点时使用 5 个有效单位阈值；中文按字、英文按词、数字按数值单元统计。明确停播规则仍走快路径。
- 后续 ASR 增长不取消在途 chunk；ASR 改写使受影响版本失效。仅一个语义请求在途，超过 4 个待发候选时合并未发内容。
- 每次模型请求携带 chunk ID、触发原因、源 revision 和最多两块前文；提供者耗时日志携带 chunk ID，调试日志记录封口、请求、合并、失效及结果。
- 打断输入不调用 EOT；停播回执后继续收到的用户文本可以正常提交。
- JEV 客户端按配置在应用内共享，保持 HTTP 客户端存活；单次取消保留连接，应用关闭时释放。并发上限现在是应用级预算，多会话负载下需单独测量排队。
- 确认现有引擎在任务清理前发出停播事件；WebSocket 优先按目标 response ID 定位，拒收清理期间旧 generation 的音频，迟到的旧目标不会停新回复。
