# 语音交互实验计划：正确性、响应延迟与异常恢复

日期：2026-10-06。状态：实验设计；首批固定事件和播放mock基线已执行，见[实施报告](../reports/2026-10-06-parallel-hardening-implementation.md)。没有新增真实模型对照实验。需求见[统一需求基线](../requirements/2026-10-06-voice-platform-requirements.md)，交付顺序见[实施计划](2026-10-05-voice-correction-implementation-plan.md)。

## 1. 当前证据能支持什么

已有控制事件回归和一个真实 Session 的重叠调用支持“有界并行实际生效”。三次固定短句、3 passed 与平均 1663.8ms 是冒烟证据。它们不证明 P95 改善、纠正正确、语义打断成功、句末衔接或无物理音频重叠。

已有 live E2E 的停播操作是点击挂断，普通回复断言是非空文本和首播；两者不能替代说话触发的打断及修正验收。JEV 专项调用耗时不能替代用户开口到旧声音停止。

复核时并发1/2的判停请求构造不一致，只有大于1时使用累计前缀；本轮已统一并有确定性回归。后续真实A/B固定这套文本/提示词与结果规则，仅改变容量，才能归因并发收益。该对照尚未执行。

## 2. 实验问题与假设

|实验|只改变的因素|要回答的问题|
|---|---|---|
|E01 调度|每会话候选并发 1/2；共享槽位固定 2|相同语义与事件下，减少多少有效候选等待？是否增加过期请求？|
|E02a 提供商容量|固定每会话并发与活跃会话数，仅改共享槽位|瓶颈是共享槽位还是 SDK 请求？|
|E02b 会话负载|固定每会话并发与共享槽位，仅改活跃会话数|跨会话是否公平，等待和失败随负载如何变化？|
|E03 连接|相同语音/文本，冷建连、就绪复用、受控重连分层|ASR/TTS 预连接省掉哪些关键路径等待？失败是否增加？|
|E04 判停与未播纠正|相同输入，既有策略/版本化策略|早判停后，补充能否保留？浪费请求、首次回复和最终正确回复延迟如何变化？|
|E05 句末衔接|相同补充时点与播放句，启用/关闭候选策略|是否只保留当前句、拒绝旧后续句、正确衔接且没有重叠？|
|E06 误打断恢复|固定误判证据及播放位置能力|能否恢复正确答案，避免重复、错误恢复及永久等待？|

优先验证安全，再看延迟。绝对延迟 SLO 尚未确认；“降低 P95”等是待检验目标。原优化计划的 P95 改善 20%保留为探索假设，不作为已经达成或用户承诺。禁止同时改并发、提示词、chunk 阈值、连接策略后将变化归因于某一项。

## 3. 实验前置条件

1. 固定语义契约：并发 1/2 的候选文本、历史上下文、提示词与结果裁决相同，只改变容量。
2. 固定身份链：Session、逻辑输入、ASR 修订、chunk、请求、回复版本、播放 epoch、句段与命令都可关联；用配置/代码版本记录快照。
3. 审计各 renderer：是否真实提供 started/stopped/finished、句段对应、样本位置、可清未来队列、可恢复。能力不足的路径单列，不承诺无缝恢复。
4. 区分服务端取消完成与客户端实际停播。现有 yield_ack 只证明服务端取消分支完成；不得直接作为 E05/E06 放行证据。
5. 为已有“旧输出自然结束后 UNCERTAIN 重要输入无出口”建立回归；噪声负例与重要补充正例使用相同初判，不能只测试丢弃噪声。
6. 输入录音/事件、期望行为与测量边界先冻结，再运行；失败、超时、无终点和采集缺失均保留。

## 4. 三层测试与判定规则

### 4.1 确定性事件回放

冻结 ASR/VAD、候选封口、分类结果与输出事件，使用可控制的完成顺序和虚拟/可推进时钟。覆盖前后候选完整/不完整/不确定、所有关键顺序、改写和更换目标回复。此层验证状态因果，不证明真实模型分类准确率或音频体验。

每个案例明确：哪些输入必须保存、是否允许提交、目标输出/句段、允许停播次数、最终回复版本、截止出口。断言最终语义关键槽位与动作轨迹，不要求生成固定措辞。

### 4.2 提供商专项

真实 ASR/TTS/JEV/LLM，固定输入与配置；冷热及重连分层。记录建连、共享槽位、SDK 请求、首文本/首音频、超时与取消。JEV SDK 请求包含网络、服务处理和解析，不能声称本地已拆出纯模型推理。

专项用于定位，不能替代带播放的整链实验。正常回复的 LLM 预生成命中与未命中分组；模块耗时不能相加作为端到端。

### 4.3 真实客户端交互

使用预定义录音，按可复现时点注入补充或打断。验证实际 renderer 输出与服务端许可对应，普通音频和数字人路径分别报告。文件麦克风覆盖可复现输入；背景回声、设备处理与硬件输出问题需要另有真实设备/少量回环音频证据。

内容判定至少包含：最终地点/约束等关键语义、补充关联、噪声是否被错误当请求、旧答案是否继续、是否出现澄清或可解释失败。模糊样本人工复核并记录判定依据，不能由生成这段回复的模型自评作为唯一依据。

## 5. 必测矩阵

|ID|场景/变体|核心断言|阶段|
|---|---|---|---|
|T01|两请求同时在途；前后结果乱序|容量受限；当前累计输入决定判停；旧前缀不回滚|前置/1|
|T02|前完整后不完整；前不完整后完整；ASR 实质改写|不提交被更新输入；受影响任务失效，有效兄弟保留|前置/1|
|T03|旧停止结果晚于最新不打断；已发 STOP 后晚到相反结果|执行前最新有效文本优先；执行后锁定。2026-10-06已确认，首批代码/回归已补；完整G1仍开放|前置/1|
|T04|非协作取消、重复结果、换 input/response|迟到结果/音频隔离；动作幂等；actor 仍能推进|前置/1/2|
|T05|连续数百 chunk、反复改写、关闭/重连|在途、待发和完成记录各有上限/清理；无累积任务泄漏|前置/1|
|T06|UNCERTAIN 噪声 vs UNCERTAIN 有意义补充；旧回复自然结束|噪声不抢话；重要文本保留并有界关联/澄清，不一刀切丢弃|2|
|T07|未播 LLM/TTS，补充“上海”“不是”及连续纠正|旧交付拒绝；累计语义保留；只交付最新许可版本|2|
|T08|完整表达、句内停顿、长句、跨 chunk 否定|正确判停；声学与语义证据分开；超时不伪装 COMPLETE|1/2|
|T09|一般补充在句初/句中/句末，旧后续音频已排队|仅当前句可继续；句末屏障；无旧后续句；衔接依据已播事实|3|
|T10|明确否定当前错误句；补充升级为否定|许可立即撤销；收到实际停播事实后交付新版本|3|
|T11|started/finished/stopped 丢失、重复、乱序、迟到|幂等且目标精确；UNKNOWN 不当 STOPPED；无重叠|3/4|
|T12|新回复已准备，允许句被提前停止/未完成|准备所依据 heard_frontier 改变时重新验证，不能盲目放行|3|
|T13|误打断，精确位置/仅句段/未知位置/原流失效|按能力续播或续答；不整段重播，不恢复已错误答案|4|
|T14|恢复中再次说话、再次有效打断、主动结束|新 epoch 能再停止；旧恢复失效；正常挂断不自动恢复|4|
|T15|JEV/LLM/TTS/ASR 失败，断连/重连|区分超时/故障/正常取消；输入保留；每次等待有出口|每阶段|
|T16|附和、背景人声、乱码、回声；问题回答上下文|负例不抢话；正例短回答不被附和规则吞掉|每阶段|
|T17|Session 接口/入口/权限/录音缺失与分页|管理员直达；非管理员拒绝；Agent 能识别缺失而非误报无异常|诊断轨道|
|T18|多会话同时判断、慢请求、会话关闭|跨会话身份隔离；共享容量、公平性、资源回收|每阶段/综合|

实时 deadline 必须针对不配合取消的 awaitable 验证。配置了 wait_for 不等于资源在截止时已经退出；应检查状态隔离、后续任务可运行、关闭能回收以及残留记录。

## 6. 测量协议

|指标|边界及分组|
|---|---|
|响应延迟（服务端估算）|服务端检测语音结束→服务端收到对应首播回执；包含检测与回传|
|响应延迟（客户端）|标注的最后有效语音样本→renderer 实际 start；同一客户端时钟域|
|有效打断延迟（客户端）|有效打断首个语音样本→目标 renderer 实际 stop；自然 finished 不算 stop|
|纠正延迟|补充最后语音样本→修正版本 start；另报当前句剩余等待及准备耗时|
|候选/JEV|封口→任务发起；共享槽位等待；客户端准备；SDK 请求；解析/actor 裁决|
|ASR/TTS|初建/就绪复用/异常重连分别统计；首尾包按统一需求边界|
|生成/交付|LLM TTFT、预生成命中后等待、TTS 首包、客户端收到→start；服务端发送→服务器收到 start 回执单列为代理|
|可靠性|误停播、漏打断、语义丢失、错误恢复、无响应、重复输出、音频重叠、锚点缺失|
|资源|每有效输入请求量、被替代请求数、完成后残留任务、共享槽位等待与关闭清理|

AudioContext、媒体样本时间与客户端单调时钟的映射及误差须记录；renderer 事件不是扬声器硬件实测。少量音频 loopback 可校验设备误差，但不与普通 renderer 样本混为同一精度。服务端发送与客户端 start 属于跨时钟事件，只有明确时钟映射和误差时才能直接相减，否则使用上表两个同域指标。

普通回复、补充纠正、恢复分别统计。ASR 首文本迟到但早已预生成、已播放旧版后再纠正等情况保留各自版本证据，不能重复拿同一首播当多个成功样本。端点确认→首播是调度指标，不替代用户说完→首播。

## 7. 对照、样本与统计

- 先冻结 ASR 事件回放做调度对照，再用真实 WAV 测整链。ASR 每次可能输出不同修订，真实实验不能强称每轮候选完全一致。
- 固定代码、模型、提示词、chunk/声学参数、渲染路径、网络条件及连接策略；并发对照仅改每会话容量，共享槽位固定 2。
- 按录音、场景、冷暖条件配对，平衡随机 AB/BA 顺序；交替运行，避免全 A 后全 B 的时间漂移。记录种子与执行顺序。
- 同一录音重复不是新的独立语义样本。有终点/锚点的“有效轮次”不等于独立样本；重采样以录音为最外层单位并保留 AB 配对，Session 相关性同样处理。分别报告短句、长句、背景声、纠正与 renderer 子类，不能靠混合均值掩盖失败。
- 报平均/P50/P95/N、配对差值和置信区间。样本不足时明确写“探索”；不承诺精确 P95/P99。
- 每一条件同时给总尝试、成功、失败、超时、正常作废取消、截止未响应、缺锚点与采集丢失。延迟分布标明“成功且锚点完整的条件分布”；无首播终点不是 0ms。
- 正常取消不计故障，但要证明累计输入最终交付。错误恢复、语义丢失和音频重叠单独判定，不能被速度收益抵消。

以下是工程提案，用于提前规划成本和结论强度，尚非批准运行全部实验或产品 SLO：

|级别|建议样本|可支持的结论|
|---|---|---|
|冒烟|每配置 3 次|链路可运行，采集是否完整|
|探索|每实验臂至少 30 轮，覆盖代表场景|定位主要瓶颈，不宣称稳定 P95|
|场景确认|每个关键场景每臂至少 100 轮，并跨不同录音|检验该场景正确性；需给不确定性|
|主要 P95 对照|预定义主要人群每臂至少 200 个有效轮次，并报告全部尝试|约十个尾部观测，仍需置信区间；不据此声称可靠 P99|
|低误打断率验证|若目标为单侧 95% 上界低于 1%，约 300 个独立负轮次零误打断|该预定义负样本人群的上界约 1%；不证明所有子类或零风险|

100 个独立负样本零错误的单侧 95% 上界约 2.95%。上述二项式上界要求预定义抽样人群及独立近似成立；不能把固定一句话重复 300 次当成 300 种独立噪声场景。大样本为实验预算提案，本轮不自动运行；先完成低成本回放与小规模探索。

## 8. 阶段门槛与报告

G0：完成输入语义统一、播放能力表、身份/计时协议、实验样本与期望结果；收录已知缺陷。本阶段只建立证据，不宣称已修复。

G1（并行补强）：T01—T05、T08/T16/T18相关回归；无过期动作或跨会话污染，长输入资源上限可测。真实重叠调用只关闭“并行启用”验证项。

首批状态：累计输入、执行前冲突、等价修订、合作/非协作取消、关闭和排队token回归已补；播放能力表已建立。G0缺真实标注oracle，G1缺完整历史资源上限及共享提供商多会话验证，均未全部关闭。固定分类标签stub通过不等于真实语义正确率，容量等待与JEV共享槽位要分别分析。

G2（未播纠正）：T06/T07通过；取消后迟到交付为零；重要输入不被静默丢弃；异常有明确终态。

G3（句末衔接）：T09—T12在各已支持 renderer 通过；实际播放许可与回执对应；新旧音频无重叠。回执不足的路径保持能力降级，不能假装通过。

G4（恢复）：T13/T14/T15通过；已执行动作不可被旧结果撤销；恢复基于可靠事实或明确续答降级。

G5（综合）：正确性与可靠性无新增退化；完成配对延迟/连接实验及多会话验证，收益与代价可解释。统计不确定性不足时继续限范围验证，不能用历史 3 条数据放行全部用户。

确定性安全用例必须零违反。真实样本中任何语义丢失、错误目标停播或重叠先定位并阻断相关能力发布。绝对延迟预算及“允许的误打断率”等须单独确认，不在本轮擅自写死。

每份报告包含：代码/模型/配置、输入清单与种子、总尝试及排除原因、Session ID与事件引用、正确性结果、分层延迟、故障、统计限制和下一步。保留可重跑数据；不要只保存最终均值。

## 9. 实验与生产模块边界

回放、故障注入与统计放在测试/实验工具。生产继续由一个 actor 裁决，版本账本保存状态，输出边界执行许可。禁止为了测试增加第二条生产状态机或让测试假回执绕过实际播放契约。

发布按能力逐项启用，纠正/句末/恢复具有独立开关；发现安全退化停止相关交付并保留输入。并发 1 仅是诊断回退；在语义契约未统一前，回退也不能视为纯容量切换。
