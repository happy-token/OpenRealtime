# PRD: Jev 承担 Turn Taking 语义判断

状态：待评审；本文是需求与验收口径，不代表已经切换生产模型。

## Problem Statement

OpenRealtime 的 Cascaded Realtime Engine 需要两类实时判断：用户当前表达是否已经完整，以及助手播报时当前语音是否要求停播。现有路径主要依赖远程大模型；其判断延迟、费用与部分误判会影响抢话和响应体验。用户希望评估并逐步让 TypeSafe Jev 承担这两类**语义判断**，同时保留已有的 VAD、ASR、双闩门和 Turn Policy，避免因更换模型而改变语音交互安全边界。

已有合成文本初筛中，Jev 与 DeepSeek V4 Flash 的整体请求平均/P90 耗时分别约为 341/402 ms 和 569/786 ms（不同模型的原提示词）。但 Jev 在困难样例中把多条未说完的表达判为完整，并误读电视、旁人和回声；声源优先提示词只在**人为提供文字化声源事实**的合成保留集上改善了打断判断，不等于具备声学说话人识别能力。当前数据不足以批准直接替换。

## Solution

为 Jev 增加可配置的服务器端语义判断提供者，首先与现有提供者并行运行但不控制动作，收集同输入的判定、各选项概率、误判、费用和端到端时序。经真实数据标注、阈值选择和独立验证后，分别决定是否由 Jev 接管语义完整度和播放期语义打断；两项可独立放量和回滚。Jev 只输出有类型的文本判断，代码负责概率阈值、等待、停播、Turn 准入与失败策略。

## User Stories

1. 作为语音用户，我希望说话中途思考时助手不会抢答，以便完成表达。
2. 作为语音用户，我希望说完后助手及时回答，而不是因谨慎阈值长期等待。
3. 作为语音用户，我希望在助手播报时说“停一下”能尽快停播。
4. 作为语音用户，我希望纠正助手刚说错的事实后能继续完成新的用户轮次。
5. 作为语音用户，我希望提出新任务时助手停止旧回复并听取新任务。
6. 作为语音用户，我希望“嗯，你继续”不会让助手误停播。
7. 作为语音用户，我希望旁人讲话、电视、回声与非语音噪声不会被当作我的指令。
8. 作为语音用户，我希望在声源不明或 ASR 转写不稳定时系统采取有界、可解释的保守行为。
9. 作为语音用户，我希望网络故障不会让我无限等待或无声丢失已经说出的轮次。
10. 作为评测人员，我希望对同一 ASR revision 和冻结的历史比较 Jev 与现有提供者，避免输入差异污染结论。
11. 作为评测人员，我希望保存 Jev 的逐类概率并离线扫描阈值，同时看到抢答与额外等待的权衡。
12. 作为评测人员，我希望区分原始六类打断准确率与最终停播二分类指标，避免分类分数掩盖误停播。
13. 作为评测人员，我希望按声源可用性、ASR partial/revision 和中文口语困难类型切片，定位失效条件。
14. 作为运行人员，我希望完整度和打断可以分别开启影子模式、灰度和一键回滚。
15. 作为运行人员，我希望看到模型请求、端到端停播/提交的平均及 P90/P95 延迟、错误和超时。
16. 作为运行人员，我希望密钥仅在服务器配置中使用，日志不记录原始语音、完整对话或密钥。
17. 作为开发人员，我希望新提供者复用现有领域接口、revision 取消和 Generation 校验，不修改公共 Realtime 协议。
18. 作为产品负责人，我希望先看到独立真实样本上的质量、延迟和成本比较，再决定是否扩大替换范围。

## Implementation Decisions

- **保持两项判断独立。** 完整度沿用现有 EoT evidence/provider 接口；打断沿用现有 Semantic Interruption Classifier 接口。它们的判断时点、失败降级和动作不同，不合并为一次调用，也不改变 Realtime Engine、Conversation Journal 或 Turn Policy 的公共契约。可选本地 FireRed 快路保持原有配置与仲裁规则。
- **完整度输入。** 每次请求给 Jev 当前累计转写及候选冻结时的已提交 user/assistant 历史；历史沿用会话现有默认上限（8 条、4000 字），只用于解决指代和短答，不把旧消息误作当前用户表达。语义结果仍需和 VAD/ASR 稳定停说闩门同时满足才能提交轮次。
- **打断输入。** 给 Jev 当前 ASR revision、边界和实际可获得的助手播报文本。当前线上接口没有可靠声源观察字段；不得把合成评测中的电视/旁人/回声说明伪装成线上可用输入。声源识别若将来独立提供可信事实，应另行约定来源、时效和缺失行为，随后重新评测。
- **输出与阈值。** 使用 TypeSafe `Choice` 的完整选项分布：完整度为 `complete/incomplete/uncertain`；打断为 `stop/correction/interrupt/backchannel/ignore/uncertain`。记录各选项概率、选择、模型版本及耗时。完整度优先根据 `P(incomplete)` 和 `P(complete)` 的离线验证阈值决定继续等待、提交或短暂待定；不要把 `confidence` 当作 `P(incomplete)`。打断可按三项停播概率合计评估动作阈值，但最终仍保留原始六类标签及“纯停播是否创建 Turn”的区别。原大模型自报置信度的 `0.8` 门槛不能直接套用到 Jev 的分布置信度。阈值在开发集选择、在独立集验收，不在小保留集上直接定生产常数。
- **运行时行为不退化。** 精确本地规则、ASR revision latest-wins、旧请求取消、播放 generation 校验和重复事件去重保持原样。EoT 错误/超时继续走现有有界 `UNCERTAIN` 等待；播放期打断错误/超时沿用现有 fail-open 处理。对模型判断为 `ignore` 的已完成非回声话语，不在未经验证前改动现有 Turn 准入策略；报告必须分别统计标签判断和实际动作。
- **等待由运行时代码控制。** Jev 不生成自由格式 `wait_ms`；完整度的 `INCOMPLETE/UNCERTAIN` 映射到现有可配置、有上限的等待窗口，避免把一次低阈值召回改善变成长期无响应。声学活动或新 ASR revision 仍能立即使旧结果失效。
- **部署与资源。** 凭据仅由服务器端注入；Jev 模型版本、问题文本、阈值、超时和提供者选择可追溯、可回滚。按无可控 KV cache 的独立请求设计，不把自动前缀命中或跨请求会话状态算作性能收益。影子调用有速率和费用上限，不能阻塞主路径。
- **隐私与观测。** 只记录脱敏后的样例 ID/切片、模型版本、原始选项概率、最终动作、延迟、失败类型与阈值版本；真实文本仅在获授权的短期评测存储中留存，并支持删除。线上遥测不新增原文或密钥落盘。

## Testing Decisions

- 以**外部可见行为**验收：是否抢答、是否误停播、停播到达时机、是否丢失用户 Turn，而非仅断言调用了某个 SDK。沿用现有 EoT evaluation、Semantic Endpoint Gate、Semantic Interruption Gate、Turn Manager 和内核抢话流程测试接口，避免新增横跨状态机的测试接缝。
- 先冻结标注方案，建立经许可、去标识、双人复核的真实音频与 ASR partial/revision 样本；包含短确认、上下文省略、句尾悬空、自我纠正、否定、长停顿、重叠说话、电视/旁人/回声、ASR 误识别和未知声源。分开发集、阈值集与从未参与选择的验收集；合成的 30/52/20 条样例仅作回归与故障定位。
- 每个候选分别执行五次重复推理并保留逐次结果；报告**独立样例数与请求数**、逐类混淆、精确率/召回率/F1、稳定错误、请求失败。完整度重点报告不完整召回率、错误提前提交率、完整表达多等候率和真实额外等待时长；打断重点报告真实打断召回率、误停播率、纯 `stop` 与新任务的 Turn 准入准确性，以及声源缺失切片。`uncertain` 的动作映射须单独声明。
- 记录模型请求与真实交互两层延迟：请求平均/P90/P95、用户停说至提交/首字语音、用户打断至实际停止播放，并分别报告超时、取消、请求成本及按历史长度分层。重复请求的耗时不能替代用户体验时延。
- 影子期按相同候选做成对比较；先验收误抢答和误停播不劣于现有路径，再看平均/P90 延迟改善与成本。完整度沿用现有独立集目标：完整判定精确率至少 99%、误截断率至多 1%，同时不能比现有 LLM 路径更差；误停播和真实打断召回率的界限在真实样本标注及基线冻结后预先登记，不以合成集目标代替。需要同时验证现有交互目标：停说至首音 P50 < 800 ms、P95 < 1500 ms，抢话至实际停播 P95 < 200 ms。Jev 请求本身约数百毫秒，后一个目标尤其依赖本地规则与声学前置，不能凭模型耗时推断达标。放量门槛还须包含置信区间、样本量和至少一个可接受的完整度概率阈值；若阈值扫描无法同时控制抢答与额外等待，则该判断保留现有提供者，不因合成集 100% 而放量。
- 演练超时、限流、无效响应、取消失败、ASR 回撤、旧 generation 晚到、无声源和历史为空；确认回滚只更改提供者选择，且不会绕过双闩门或重放被取消的语音。

## Out of Scope

- 让 Jev 直接读取音频、执行 VAD、说话人分离、回声消除或修复 ASR。
- 重写 Turn Policy 状态机、Conversation Journal、公共 Realtime 命令/事件或回复 Brain。
- 因本 PRD 直接切换生产模型、更改停播 fail-open 策略或开启全量灰度。
- 引入或假设可控 KV cache；不开发跨请求会话缓存服务。
- 将文本合成集上的准确率当作真实音频交互的上线证明。

## Further Notes

- 先前同条件五次合成文本初筛：Jev 挑战集完整度准确率 87.5%、六类打断准确率 66.7%；DeepSeek 分别为 99.2% 和 81.7%。Jev 的提示词实验仅在新增的 20 条文本保留集上将完整度从 65% 提至 70%，并将六类打断从 75% 提至 100%；后者依赖模拟声源观察。五次推理不能充当五倍独立样本。
- 官方 TypeSafe 文档说明 Jev 接受文本/结构化 `state`，`Choice` 返回每个选项的概率及汇总置信度；它不是语音模型，也没有公开可控 KV cache 接口。参考：[State](https://docs.typesafe.ai/concepts/state.md)、[Choice](https://docs.typesafe.ai/primitives/choice.md)、[HTTP API](https://docs.typesafe.ai/api.md)。
