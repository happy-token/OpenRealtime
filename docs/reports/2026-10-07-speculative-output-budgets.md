## 复现与修复

基线命令 `uv run pytest tests/realtime/test_speculative_resource_limits.py -q` 首次四项失败：候选文本保留 262144 字节、PCM 保留 16777216 字节；两个缓存都在旧供应商真实退出前发起新请求。

|边界|最终行为|
|---|---|
|缓存保护|追加前检查文本 UTF-8/PCM与字幕字节、块数、音频秒数；独立 timer 清理已完成候选的绝对驻留|
|未正式使用的超限候选|清缓存并记录 budget_exceeded；真实旧资源释放后 budget_bypass；保持完整输入/上下文|
|已经正式消费|deque 排空、背压、同一供应商；超过单包契约明确失败，不重播已输出内容|
|异常内存|存轻量、有限消息的异常副本，不保留 traceback/cause/context；TTS 文本对比用增量 hash/长度|
|候选退休|软退休未知供应商 await，唤醒内部队列，保留唯一资源归属；禁止把 failed retiring 候选重新 claim|
|双工租约|正式文本与配对 TTS 共用租约，未命中同样受保护；空回复解除租约|
|关闭|控制器、缓存、Core、Managed 共用各自 owned close；取消等待者/重复关闭不提前确认或注销|
|失败关闭|actor 独立关闭证据 writer、Core 结束事件流；Managed 保留 suspended 删除保护、退出事件泵，重复关闭保持原失败|

独立审查后的真实红回归还复现并修复：自然 `finally` 被取消；异常清理中的第二次取消；普通 miss/bypass 清理失败未隔离；旧正式文本被新候选 TTS 混入；空回复永久占租约；正常 Brain 关闭后 END 队列等待；失效候选升格为 formal；只有预生成时 Core 提前关闭及 Managed 取消关闭后提前注销；供应商关闭失败跳过证据 writer 收尾、Core 事件流无法结束；旧清理结束后越过关闭意图启动新供应商。

软退休的取舍是：TTL 只限制缓存驻留。真实供应商尚未结束时仍占单槽、禁止新请求；不能把 100 ms 等待称为供应商退出。正式响应仍受既有 Core 绝对截止和取消契约控制，不保证任意供应商可强制退出。关闭等待者可取消，后台 owned 清理仍保留删除保护。

## 验证

- 资源文件 50 项；包含 8 MiB 文本、16 MiB PCM 和非法采样率 PCM 的实际 tracemalloc 留存检查，真实供应商结束后缓存留存低于 1 MiB。供应商构造大包的瞬时峰值不计作缓存上限保证。
- 100 delta 正式文本/PCM 在小预算下完整输出，只调用一次供应商；每次消费检查缓存字节/数量上限。
- 真实 Cascaded Core 的 bare、speech direct、speech prepared 三配置验证空回复失败后下一轮可回复。
- 真实 actor 自动预生成触发 Core/Managed × text/speech/tool-chat 六配置关闭；两配置清理失败保留历史删除保护并退出事件泵，同时关闭实际证据 writer、结束 Core 事件流；四项关闭与准入竞争回归确认关闭后不启动新供应商。
- 最终全 Python、限定 Ruff/Mypy 和独立审查结果见下方最终记录。

测试使用受控供应商与内存存储。没有调用真实 JEV/ASR/LLM/TTS，没有修改数据库或重启用户 3010/8765/8766 服务；没有前端修改，未重复浏览器测试。本批证明缓存及生命周期边界，不代表真实语音延迟改善或物理播放/G3验收。
