# 2026-10-07 普通补充句末等待期间的候选预生成

## 本批范围

前置预算及关闭归属已提交 `f1359c0`。本批在既有 actor、ResponsePrefetchController 和 Core 投影中接入普通补充候选，未新增业务 actor、播放队列或生产模块。独立构造开关 `sentence_handoff_prefetch_enabled` 默认 **False**，没有启用或重启用户服务。生产正式回复仍受实际停播、最终 ASR 关联和实际已听投影控制。

这是 ADR0137 的局部接入，不能关闭一般补充完整衔接或 G3。候选只用 **confirmed heard**，不把仍获播放许可的句子提前当成已听。物理已听文本改变时需要实际投影重建，因而不保证延迟改善；提前完成许可句的条件投影、非合作供应商失配清理、真实 renderer/provider、异常恢复及其他轨道仍开放。

## 处理流程

1. 既有语义打断结果与明确补充关联签发当前句许可，停止旧版本新增交付，生成取消和物理句末等待分别处理。
2. 用户已停止说话、旧生成 yield 已确认、许可未撤销且未超时，才允许一个累计输入候选。候选绑定 input identity、generation、原始 ASR 文本、累计文本、父 turn 和精确许可 ID。
3. 每份许可最多一次准备。迟到逐字 ASR 改写只失效候选，不循环提交新供应商；再开口、纠正、STOP、未知位置或撤权同样失效。上下文构建 await 后再次核对 actor 权限；非合作投影返回也不能恢复撤销权限。
4. Core 准备上下文时保留来源身份，但隐藏已被累计输入覆盖的旧 USER 文本；正常正式提交采用同样过滤，避免重复原问题或无谓缓存失配。
5. 实际停播回执仍控制 AsrCommitRequested。确认停止但位置未知，可以释放输入等待，却清掉候选。最终 ASR 只在 SUPPLEMENT、父引用、累计文本和 generation 一致时保留候选；新问题、未知关联、纠正或正文变化失效，句末标点变化兼容。
6. 正式 Brain/TTS 使用 ADR0141 原缓存租约与实际上下文摘要复验。实际已听前沿不变可以命中同一供应商；新增已听内容必须先结束旧候选资源，再按最新投影生成。停止前候选文本/PCM只在私有预算缓存，没有新回复帧外发。

## 回归证据

首次 `uv run pytest tests/realtime/test_sentence_handoff_prefetch.py -q` 六项失败：真实 actor 授权的普通补充在实际句末等待期间未启动供应商。修复后同路径通过。

新增 20 项：

- 六项最初 actor/cache 回归：最终正文/标点取舍；重新开口、纠正、STOP、未知位置撤权。
- 每份许可最多一次，八次迟到文本增长不逐字请求；默认关闭保持原正式生成时机。
- 真实 Managed/Core/Journal/Bridge × 文本/语音缓存 × 600/1000 样本四场景：600 样本没有新增完整已听句，准确两次供应商调用（原回复加候选，正式命中）；1000 样本新增第一句，准确三次（原回复、候选、正式重建）。Stop 前新回复外发帧为零，最终投影/摘要与真实已听上下文一致。
- 四项阻塞上下文构建后重新开口/纠正/未知位置/关闭：构建忽略取消并返回也不得调用供应商。
- 三项最终同文本但关联变为新问题/未知/纠正，不保留普通补充候选。
- 复核发现 UNKNOWN terminal 保留候选的真实红回归；修复后正常释放 ASR 等待并失效候选，不把未知位置当作缓存复用依据。

定向 74 项、四个相关生产模块 Mypy、七个相关 Python 文件 Ruff 通过。最终 `uv run pytest -q`：**2257 passed、69 skipped、3 subtests passed，50.53 秒**。两位既有独立代码/Python 审核批准，`git diff --check` 通过。供应商、ASR 和播放位置受控，没有真实模型/录音/物理扬声器性能实验，没有数据库变更或用户服务重启。
