# Brain 尝试身份、首输出前沿重验与真实清理确认

日期：2026-10-07。对应 ADR0137、实施计划阶段3。前置提交为 `5ed79b8`。本批完成生成尝试隔离、首次语义输出前的有限重生成，以及生产模型流的清理确认；阶段3/G3仍未完成。

## 行为与边界

一次公开回复可以在**首次文本、工具请求或委派请求发布之前**重新生成。每次尝试有独立 `request_token`，六种 Brain 事件及工具反馈都绑定该令牌；取消也精确匹配。公开 `response_id` 在此期间保持不变。初次请求加最多两次重试，共用原首文本截止和总响应截止，取消、重新投影和重新请求不会刷新预算。

每个首语义输出到达时，核对当前用户文本、输入关联和历史模型投影指纹。已听内容变化时先确认旧尝试关闭，再使用最新稳定投影重试。取消未确认就结束回复并隔离模型会话，禁止启动替代请求。旧令牌的 Started、Text、Tool、Delegation、Completed 和 Failed 都不得改变新尝试；缺令牌显式失败并关闭故障 delegate。

`BrainResponseStarted` 只标记内部尝试开始。公开 `ResponseStarted` 在接受首语义输出时发布；文本到来才建立模型语音/TTS。只有委派请求的有效回复仍能正常完成，不创建空语音记录。工具、委派已经公开后不使用同一回复 ID 重放。

公开后发现前沿变化，本批立即撤销回复交付许可、通知停止并明确失败，要求新公开回复版本。**自动生成新版本并衔接仍待实现**。最后文本之后、Completed 之前以及最终装饰队列/传输交付时的完整前沿重验也继续开放。本批失败撤权覆盖已知失败等待期间的排队 PCM，不能替代这些最终重验。

## 生产清理归属

此前，关闭最外层 async generator 不会自动关闭各层 `async for` 持有的内层流，缓存超过100ms便 detach 也不能证明资源已释放。本批用一个基础设施 `owned_async_iterator` 显式传递关闭，扩展既有模块，不新增业务控制器。

|路径|确认方式|未确认时|
|---|---|---|
|Legacy capability|注册先于任务启动；对象身份校验释放；实际流及工具反馈通道关闭后才确认|保留 owner，取消明确报错，Core 隔离|
|VoiceRuntime / BrainStreaming / ChatBrain|显式关闭所持有的迭代器；工具 delayed relay 保留清理错误|错误传回 owner，不作为成功关闭|
|文本预取|已提交 consumer 退出/失效时等待真实 producer 完成；普通候选 invalidate 仍100ms有界，并保留残留任务归属|不能把普通 invalidate 返回当取消确认|
|文本及音频预取|模型与 TTS 流显式关闭；audio/drain task 清理异常传回|普通供应商请求失败与清理失败分别保存|
|Chat HTTP SDK|保留实际 `to_thread` worker 和 HTTP close future，两者都结束后确认|不取消 Future 来伪造工作线程退出|
|工具计划/反馈 SDK|shield 实际线程；取消后保持归属直到线程退出|使用现有传输超时，Core 有界等待并隔离；本批没有新增工具 HTTP 提前中止能力|

Cancel 的等待者被取消，不会再次取消正在执行 finally 的 owner。所有重复、并发或被取消后的 close 调用加入同一个原清理任务，关闭等待者本身退出不表示资源已释放。具体 socket/TTS 清理错误保留为原因，不覆盖原始响应超时或打断取消原因。

Core 使用异步等待预算控制取消/隔离的调用者等待，保留未完成任务。**永久不协作 provider 的整个 Core shutdown 尚无统一硬截止**；不宣称资源可被强制释放或所有 close 都具有 wall-clock 上界。

## 失败输出与句末许可

总超时、首文本超时、供应商失败、身份协议失败或公开后前沿过期，先同步关闭 Core 交付许可，再执行 actor 撤权和供应商清理。生产装饰队列及 Bridge 拒绝已经取出或仍在排队的旧 PCM，清理等待窗口不再继续放行音频。

正常 `barge_in_floor_claim` 取消保留现有 actor 的句末规则，不执行通用失败撤权。活跃模型已经产生首句但仍在生成时，一般补充取消生成后，当前句许可仍有效；不额外发出立即停止命令。明确纠正仍由既有 actor 撤销许可。

## 验证

所有新模型、工具线程、HTTP 和 TTS 故障均为受控本地替身，没有调用真实供应商。Managed/Core/Bridge 和版本 actor 使用生产实现。

- 请求身份：启动前取消、满 Started 队列、旧 owner callback、令牌类型及六类旧事件隔离，缺身份 finite/blocked/flood delegate 故障退出。
- 前沿：两次真实播放进度推动最多三次尝试；第三次变化耗尽预算；原首文本截止覆盖取消及重新投影；文本/工具/委派首次公开和公开后停止。
- 清理：裸流、文本及音频缓存 hit/miss 的满队列取消；ChatBrain→SDK 实际 HTTP close/worker 确认；工具计划/反馈线程及取消等待者/关闭等待者竞争；socket/TTS finally 抛错不确认；普通供应商请求失败可以确认释放。
- 交付：总超时、公开后前沿变化、缺身份的实际 Managed 排队 PCM 在 provider 清理暂停时已撤权，Bridge 不发音频；清理传输错误保留原失败/取消终态。
- 正例：活跃生成中普通补充保留实际当前句许可，只产生一个带许可的停止操作。

最终检查结果见本文件末尾。没有重启用户服务、迁移用户数据库或执行真实物理 renderer 验收。
