## 页面结构建议（待逐项确认）

整体看板：
- 顶部时间范围、角色、引擎、供应商、状态筛选和 Session ID 精确搜索。
- 首屏：会话量/活跃数、有效回复率、用户停说到首播 P50/P95、有效打断开口到停播 P50/P95。
- 趋势：两类体验延迟、异常率、会话量；支持定位同一时间窗口内的异常会话。
- 模块：ASR、语义端点、模型、TTS、工具/检索、网络与播放，各自样本数、覆盖率、P50/P95、错误和超时。
- 会话表：开始时间、Session ID、角色、时长、轮数、状态、回复延迟、打断延迟、异常数、采集完整度，点击进入详情。
- 用量与成本作为辅助区域，不替代体验与故障指标；实际计费单位及价格版本尚待确定。

单会话详情：
- 顶部身份、角色、引擎/供应商、配置版本、持续时间、状态和日志完整度。
- 逐轮对话与同一轮的执行瀑布图联动，明确语音结束、端点提交、首文本、首音、客户端首播。
- 打断独立展示检测、判定、取消发送、客户端停播、ACK，以及旧输出关联。
- 错误/超时/取消/恢复可以筛选和直接定位，事件保留证据来源。
- 原始日志分页、关联 ID、按模块检索、JSON 导出以及 Agent 查询接口。
- 已确认音频回放纳入首版：默认采集所有会话的用户与助手双向音频，与转写、执行事件和延迟时间线同步；无录音时明确显示未采集。

## 数据能力边界

已有 telemetry、debug log、journal 和部分客户端回执。统一诊断接口、稳定分页、精确停播回执及一致的延迟口径仍需补齐。
当前 ADR-0055 明确原始音频留存默认关闭；音频回放不能通过仅调整页面获得，需明确录音范围、保留周期与采集开关。
缺失指标不填 0；用户体验指标不以服务端发包时间冒充客户端实际播放时间。
预取、LLM 与 TTS 流式阶段可能重叠，模块耗时不可简单相加作为总延迟。

## 当前访谈问题

第一项已确认：首版需要真实双向音频回放，与时间线联动；采集范围见第三项决策。
第二项已确认：音频默认保留 7 天，可手动标记需长期排查的会话以避免自动到期；到期后保留日志与指标，页面明确显示音频已到期。
第三项已确认：所有会话默认录制用户与助手双向音频。此决策替代此前按需采集建议及 ADR-0055 的默认关闭策略；实施时同步更新配置默认值和相关文档。录制失败明确显示采集失败，不能将其视为无异常。
第四项已确认：看板首屏以体验、延迟和故障为主；Token 用量和费用仅放辅助区域。
第五项已确认：每个模块均统计响应延迟，同时提供整体聚合与单会话/单轮明细。
后续再依次确认总览首屏、异常定义、会话表默认列、详情布局和 Agent 获取范围。

## 模块延迟统计范围（按用户要求补齐）

- 输入与 VAD：输入接收、语音起止检测、结束确认等待。
- ASR：建连、首 partial、最终文本尾部等待。
- 语义端点：候选等待、分类器调用、提交等待。
- Brain/LLM：上下文准备、请求到首文本、完整生成；预取单独标记。
- 记忆与知识：检索、读取、上下文组装。
- 工具与外部 Agent：排队、授权等待、调用执行、首结果及完成。
- TTS：建连、首文本到首音、合成完成及音频块间隔。
- 传输与播放：音频下行、客户端缓冲、调度到首播、欠载；跨端计时显示校准误差。
- 打断：重叠检测、语义判定、取消发送、客户端取消执行、停播回执；独立保留 interruption_id。
- 录音：采集、上传、可回放状态与失败，不混入主交互路径耗时。

统计按角色、引擎、供应商/模型、时间范围、结果状态筛选。每项显示样本数、覆盖率、P50/P95/P99、错误率和超时率。
单轮保留真实开始/结束、关联标识和测量来源。并行模块用瀑布图展示，不直接相加当作整体延迟。
以上为需实现的采集清单，不代表目前已经全部具备。设计时区分已采集、待采集和无法精确测量的项目。

## 2026-10-04 模块耗时口径核查

| 阶段 | 主指标 | 起止点与限制 |
| --- | --- | --- |
| ASR 首文本 | `asr.speech_start_to_first_text` | 主机收到 VAD 开口事件到首次非空识别文本；包含识别所需音频积累和 VAD 检测误差。缺少 VAD 不作推算。 |
| ASR 最终文本 | `asr.last_frame_to_final_text` | 最近输入帧到最终文本交付；不等于用户停说后的识别处理耗时。 |
| LLM TTFT | `llm.request_to_first_text` | 实际模型请求到首个非空文本增量；并非逐 Token 间隔，未采集 TPOT。 |
| TTS 首包 | `tts.first_text_to_first_audio` | 首段文本交付到首个非空音频包；不含前置 LLM。 |
| 语义判停 | `turn_policy.eot_classify` | 整个判断调用开始到返回，覆盖规则/关闭分类器/模型路径，含失败取消状态。模型调用另有 provider 指标。 |
| 语义打断 | `semantic_interruption.classify` | 整个判断开始到返回，覆盖规则/模型/双意图回退路径，不等于实际停播延迟。 |

旧 `asr.input_to_first_text` 在真实日志出现 P95 21573.899625 ms 与最大 2139648.567584 ms。代码从该 generation 的第一帧音频计时，静音及说话等待会进入统计，所以不能当作 ASR 模型处理耗时。保留原始记录，改名为“音频输入 → 首文本（含静音等待）”，不回填新口径。新增 VAD 锚点指标后已重启本地语音服务，新会话开始采集。确定性测试覆盖 20 秒静音后 180ms 首文本，以及真实输入流水线传递 VAD 锚点。

旧 `tts.time_to_first_audio` 实际起点为回复启动，改名“回复启动 → 首音频（含生成）”；`brain.time_to_first_text` 含编排，改名“回复请求 → 首文本（含编排）”。保留并解释辅助指标，六项核心指标缺少样本时仍显示未采集。当前分位数覆盖全部已计时尝试，包括失败与取消；页面说明该统计口径并显示取消数。

### 本地日志存储核查

本地 `.env.local` 未设置 `VOICEAGENT_STATE_BACKEND`，运行时默认 memory。此次重新加载采集代码时，旧进程的内存日志被清空，不能恢复，先前查到的 ASR 异常样本仅保留了核查数值。现已显式配置 `VOICEAGENT_STATE_BACKEND=postgres`。通过真实 RuntimeTelemetry 写入一个无业务内容的测试事件，读取控制接口后重启服务再读，验证事件仍存在，随后仅清理该测试事件。此配置修复确保后续日志持久化，不补造历史记录。
