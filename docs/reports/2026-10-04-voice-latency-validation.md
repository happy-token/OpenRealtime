# 语音延迟优化验证记录

日期：2026-10-04。环境：本地开发服务；JEV `jev-1.13.0`；回复模型 `deepseek-v4-flash`。

## 接通的链路

普通输入按稳定 chunk 判断，并在稳定句尾/停说时准备 LLM；正式回复通过同一个 Journal 上下文投影复用候选。首版默认不提前 TTS。工具意图由现有 VoiceRuntimeBrain 过滤，不提前执行工具。

预生成候选在 ASR 实质变化、恢复说话、目标变化、提交被拒绝、最终文本不匹配或会话关闭时失效。纯末尾句号/感叹号变化可以复用。观察事件区分 prepared/skipped/hit/miss/discarded/invalidated/failed；hit 附带已缓冲字符数、预生成提前时间、首段是否已经就绪。提前时间不是节省耗时。

## 真实模型冒烟测试

复现入口：加载与服务相同的 `.env` / `.env.local` 后运行 `.venv/bin/python -m demos.jev_turn_demo`。输入为合成 ASR/VAD，停播回执立即确认，未播放音频。

| 场景 | 结果 | 端到端协调器耗时 | 模型调用 |
| --- | --- | ---: | --- |
| 普通问句 | 提交用户输入，不停旧回复 | 611.0ms | EOT 1 次 |
| 地点纠正 | 请求停旧回复并提交输入 | 1074.5ms | 打断 3 次；EOT 0 次 |
| “嗯，我在听，你继续讲” | 丢弃附和，保持旧回复 | 1.7ms | 0 次，精确规则 |

纠正场景包含低置信度结果；最终停说后按现有保留用户输入策略接管，不将它包装成高置信度分类。此次修复了前一块不确定、仍有待判断内容时提前接管的问题；在途或待发候选存在时，非停播证据不能提前裁决整个输入。停止词若前面已有块，交给带短上下文的分类请求，避免跨块否定被局部规则截断。

停说后的无标点尾段作为一个候选封口，超过 64 个有效单位才继续分块，减少停说后按 5 字重复拆分的请求。

## JEV + 回复 LLM 对照

复现入口：`.venv/bin/python -m demos.voice_prefetch_demo`。同一短输入，合成 ASR/VAD，使用真实 JEV 与回复模型；计时终点是服务端首段文本，不包含 TTS、网络下发及客户端实际播放。

| 模式 | 停说→提交 | 停说→服务端首段文本 | 回复请求数 | 缓存 |
| --- | ---: | ---: | ---: | --- |
| 不预生成 | 556.4ms | 1214.9ms | 1 | miss |
| 预生成 | 398.0ms | 786.0ms | 1 | hit |

预生成提前启动约 398ms，提交时首段尚未就绪，提交后继续跟随相同生产者。仅每种模式一个样本，运行顺序固定，网络及连接暖机不同；不能据此估计可靠 P50/P95/P99，不能把差值全部归因于预生成，也不能当作实际首播收益。

## 自动回归重点

- 稳定输入才启动预生成；ASR 增长失效；纯终止标点变化复用。
- 未提交时不交付候选回复；提交后只产生一次匹配的 LLM 请求。
- 引擎预生成使用与最终回复相同的 Journal 上下文；上下文变化拒绝旧缓存。
- 打断 chunk 不准备回复；会话结束清理候选。
- 不配合取消的旧生产者不会无限阻塞失效；旧文本不能回到新缓存。
- 不确定前块不能抢在后块判断前接管；精确附和组合不误停；跨块停止词带前文判断。

最终验证：

- Python 全量：1451 passed、62 skipped、3 subtests passed。
- 前端全量：1211 passed、7 skipped（266 个测试文件通过，3 个文件跳过）。
- 真实豆包 TTS/ASR：4 passed，包含双向增量 TTS 及真实音频的 partial/final 识别。
- 修改文件 Ruff 检查与 git diff --check 通过。
- 无活跃会话时重启本地语音服务；观测健康返回 ok，遥测及调试日志使用 PostgreSQL，未丢弃事件。

额外回归锁定：已判断块被 ASR 改写时清除旧短上下文；缓存失效唤醒消费者且不重发旧问题；默认仅提前 LLM 与显式提前 TTS 两种装配；精确附和组合与否定后的局部停止词。

## 仍需测量

真实录音回放的分类准确率、请求预算及分位数；完整 ASR→判停→LLM→TTS→客户端实际首播；用户开口→旧音频实际停播；跨机器时钟映射误差及数字人播放能力差异。当前结果不证明整体 P95 改善目标已达成。


## 规则插件模块化验证

规则词表、提问/partial/跨 chunk 保护及规则优先路由已独立为 `RuleFirstInterruptionClassifier` / `ExactInterruptionRules`。新增规则接口与默认规则替换回归，确认命中不调用模型、未命中只调用一次模型且原样转发请求、自定义短停播规则可以走协调器快路径。模块化后的全量 Python 结果为 1462 passed、62 skipped、3 subtests passed；Ruff 与 git diff --check 通过。无活跃会话时重启服务，观测健康返回 ok。

## 链路职责拆分验证

- `ResponsePrefetchController` 独立管理候选去重、上下文构建、任务取消、缓存失效与会话清理；协调器只提供候选及当前输入校验。
- `SemanticChunkScheduler` 独立管理单飞队列、超限合并、ASR 修订失效与最近两个已判断块；协调器保留会话状态转换和模型结果应用。
- `PlaybackOutputController` 统一浏览器与数字人的路由、取消、重置及音量；取消 generation 后拒绝迟到音频和异步浏览器回退。实际播放位置仍由各 renderer 提供，未将估计位置表述为真实停播确认。

验证：Python 全量 1465 passed、62 skipped、3 subtests passed；随后新增的预生成控制器独立测试 3 passed。前端全量 1215 passed、7 skipped，267 个测试文件通过。修改文件 ESLint、Ruff 通过。

全项目 TypeScript 检查仍受到既有问题阻塞：`src/app/api/user/model-services/route.ts` 导出了 Next.js 路由不支持的 `isPersonalModelKind`，生成的 `.next-dev/types` 因此报错。本次修改的播放控制器和 hook 未出现类型错误。本次职责拆分没有重新测量真实模型延迟，不据此宣称新增的延迟收益。
