# Jev 运行时接入验证

日期：2026-10-01。已实现判停与打断两个插件，并配置本地服务端同时选择 Jev。
本地密钥只保存在 Git 忽略的服务端环境文件中；配置需在下次服务端启动时加载。

## 验证范围

`demos/jev_turn_demo.py` 调用真实 Jev，通过新协调器输入合成的 VAD/ASR 事件，
由 Demo 回复 ASR final 和停播确认。验证插件→协调器→让出话轮／最终提交路径，
没有测试真实 ASR、浏览器停播时间、音频回声或网络传音。
输出包括标签、置信度、概率和模型版本；所有文本为固定合成场景。

## 耗时与超时修正

初始 800ms 预算下，三种场景的模型请求均超时，由运行时兜底。
因此那轮的 committed 不是模型验证成功。单独核查异步适配器请求耗时约 1.26–1.42 秒。
改为 2000ms 的试验预算后，三种场景均观察到真实模型结果，错误日志为空。

| 场景 | 模型结果 | 协调器动作 | 事件链耗时 |
| --- | --- | --- | --- |
| 普通天气请求 | complete，0.99 | 提交新轮次 | 1209.4ms |
| 地点纠正 | correction，0.90；complete，0.92 | 让旧助手响应停播，再提交 | 1079.1ms |
| “嗯，我在听，你继续讲” | backchannel，0.92；complete，0.76 | 让助手停播并准入用户输入 | 1335.2ms |

附和未被抑制，因为默认抑制阈值为 0.95。完整度 0.76 低于 0.8，实际映射为 uncertain，
随后经过运行时等待提交。模型标签、运行时动作必须分别理解。

再用 0.9 附和阈值单次复跑，模型的附和置信度变为 0.88，仍然发生接管。
普通／纠正／附和耗时分别 1405.4／1067.7／1581.3ms。
这说明调低一次阈值并不保证稳定行为；不能针对三个 Demo 场景宣称阈值已经校准。
原始输出在本地 `tmp/jev-coordinator-2026-10-01*.jsonl`。

当前每次调用新建、关闭异步 SDK 客户端，不能复用连接。
之前分类评测脚本在一批请求中复用同步客户端，约 300ms 的结果不可直接用于这个实现。
下一步性能优化需要明确会话资源的创建／关闭契约，再复用连接；本次没有绕过取消与关闭边界。

## 已提供的控制

- 判停、打断分别选择 `llm/jev`；回复 Brain 继续使用原来的 LLM。
- Rich 请求携带历史、当前文本和状态，空历史合法；声源缺失标为 unknown。
- 模型版本、请求期限、并发、判停最低置信度、稳定附和抑制阈值可配置。
- 异步取消传播，HTTP 客户端及时关闭；实时路径关闭 SDK 自动重试。
- 不完整／不确定的等待、目标响应取消、ASR final 准入仍由协调器控制。

自动测试覆盖 rich 输入、全部六类打断、低置信判停、非法响应、取消、超时、故障传播、
提供者构造，以及 Jev 适配器通过协调器的实际让出／最终提交／附和阈值行为。
配置和重跑步骤见 [使用教程](../TURN-COORDINATION.md)。
SDK 调用形态依据 [官方 API 合约](https://docs.typesafe.ai/api)，使用异步 SDK `0.7.2`。
