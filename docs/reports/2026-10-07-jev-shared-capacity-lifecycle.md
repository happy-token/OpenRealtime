# 共享 JEV 容量与关闭边界

日期：2026-10-07。对应 ADR0135 的共享提供商验证；G1真实负载/配对验收仍开放。

## 问题与修改

`JevClient.choose` 在入口检查关闭状态，但随后等待共享槽位和 SDK 连接准备。owner 在等待期间关闭时，cold 模式仍可能创建连接/发请求；shared 模式的连接准备持锁时，close 原本等待锁后才撤销准入，也会允许准备中的请求继续启动。

先新增真实适配器的受控 SDK 回归，复现上述三种错误。修复保持原 asyncio.Semaphore 与连接栈：close 在等待连接锁前立即撤销准入，取得槽位及连接准备完成后重新检查。拒绝后的 slot 仍由 finally 归还，fresh SDK context 仍退出清理；不新增模型调度器、业务actor或全历史账本。已经发送的调用取消仍由所属会话执行器负责，close 未被改成全局会话取消。

## 验证

- 新增7项：cold/shared 排队时关闭；cold/shared 连接准备时关闭；混合判停/打断适配器按等待顺序进入共享2槽位，取消首个等待者后跳过该请求；实际两个不同Session/Thread的actor共用1槽位，关闭A取消其请求后B可继续判停和最终提交，B上下文正确。
- SDK以事件屏障控制，检查实际请求次序、峰值在途数、连接实例数、取消后的槽位归还；不靠固定长sleep制造顺序。原JEV适配器加新测试26 passed；加执行器回归30 passed。
- 全量 Python：1913 passed、69 skipped、3 subtests；提供商模块Mypy、限定Ruff及diff检查通过。独立review复跑49项通过并批准。

本批没有调用真实JEV网络，不改变模型、提示词、每会话并发或共享容量。受控FIFO通过不等于跨会话轮转公平策略或真实高负载公平性；未实施会话配额，也未证明所有共享等待者的全局内存上限。真实网络、模型准确率及并发1/2的配对延迟仍按E01/E02执行，G1不能关闭。

未重启用户服务、变更用户数据库或push。其他阶段继续开放，下一主链任务仍为ADR0137当前句许可、未来音频清理和heard_frontier交接重验，再实施ADR0138恢复。
