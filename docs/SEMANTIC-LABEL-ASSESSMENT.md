# 判停与打断标签调研评估

评估日期：2026-09-30。范围：当前代码、模型官方资料与运行时行为。本页是改进建议，新增字段和动作尚未实现；现行接口见《判停与打断插件合约》。未运行外部模型，因此不提供模型性能排名。

## 结论

值得优化。当前判停的 `complete/incomplete/uncertain` 足以承接普通完整性模型；打断的六个标签覆盖了常见插话，但完整性、交互意图、输入有效性和模型故障需要分开表达。建议保留现有插件适配能力，增量引入结构化结果，并由统一对话策略决定动作。

上一轮历史应当是可选输入。上下文模型需要它来区分回答和附和；当前轮文本模型、音频模型不应被迫消费历史。缺失或截断历史必须显式表达。

## 外部方案的标签含义

| 方案 | 官方定义或能力 | 对项目的启示 |
| --- | --- | --- |
| [Smart Turn](https://github.com/pipecat-ai/smart-turn/blob/main/README.md) | 直接使用当前轮音频做 endpoint 判断，官方说明无需上一轮音频 | 文本历史不是所有模型的必需输入；接入还需要明确的音频合约 |
| [TEN Turn Detection](https://github.com/TEN-framework/portal/blob/main/content/docs/ten_turn_detection.md) | `finished/unfinished/wait`；wait 表示要求助手暂停或停止说话 | wait 是控制意图，不能直接映射为 incomplete 或 uncertain |
| [Easy-Turn](https://github.com/ASLP-lab/Easy-Turn) | 声学与文本结合，`complete/incomplete/backchannel/wait`；wait 包括暂停或结束对话请求 | 同一句话可同时完整、要求等待；附和需要单独处理 |
| [TurnSense](https://github.com/Baiji-Team/TurnSense) | `complete/incomplete/invalid`，评测包括非语言发声 | invalid 与模型不知道答案不同，需要输入有效性维度 |
| [LiveKit](https://docs.livekit.io/agents/logic/turns/) | 文档定义无转写的误打断，并提供恢复讲话的策略 | 暂停播放、最终取消和误打断恢复需要有不同生命周期 |

这些分类体系的任务不同，不能按标签个数判断优劣。各项目公开的准确率和延迟不构成本项目同一环境下的横向验证。

## 当前代码核查

### 1. 完整性不等于允许回复

`server/turn_policy/eot_classifier.py` 的三分类包含两个语义结果和一个不确定结果。`server/realtime/capabilities/turn_manager.py` 的 `_resolve_semantic_endpoint()` 会对 incomplete/uncertain 有界等待，文本稳定后仍可提交。

因此将外部模型的 invalid 映射成 uncertain，不能保证丢弃噪声；将“等我一下”映射成 incomplete，也不能保证持续等待用户恢复。需要独立的有效性和控制意图，再由策略决定是否回复。

### 2. 打断标签混合了不同维度

`stop` 是控制意图，`correction/interrupt/backchannel` 是交互意图，`ignore` 接近动作，`uncertain` 是判断状态。一句话“别说了，改成查上海”同时包含停止旧回答和新请求，单一 stop 会丢失后半句的作用。

局部文本必须允许意图随 revision 更新：早期“别说了”可以立即停播，最终累积文本仍需保留并进入新请求判断，不能因为早期纯 stop 永久丢弃后续内容。

### 3. 分类结果与实际动作有意分离，但需要可观测

`semantic_interruption.py` 的 `completed_interruption_creates_turn()` 为避免丢失真实用户发言，对模型来源的 backchannel/ignore/uncertain，最终完整转写仍允许创建轮次；精确本地附和规则才可以抑制。因此模型返回 ignore 不等于最终忽略输入。应记录模型判断、实际动作及覆盖原因，方便排查“标签正确但行为不符”。

本地规则包含“嗯”“嗯嗯”“好的”等。助手讲解中的“嗯”与助手提问后用户回答的“嗯”应成对评测，确认短回答不会被附和规则误吞。文本短、词语相同不足以决定标签。

### 4. 故障不能伪装成语义判断

打断 Gate 在模型异常或超时时，对非空文本产生 `interrupt/confidence=0/source=fallback`。置信度阈值仅作用于正常模型结果，而 `should_stop` 根据标签判断，因此故障降级仍能停播。这是当前保留用户输入的策略选择，但故障与用户明确打断需要分别记录，并允许策略配置。

建议区分 timeout、unavailable、invalid_output 和正常低置信度。保留输入的策略与是否立即取消播放分别决策，避免用虚假的确定标签代表系统错误。

## 建议的结构化输出

以下为下一版设计建议，不是已经支持的字段。无需每个模型都预测全部维度；不支持的维度返回 unknown，由适配层保留原始结果。

| 维度 | 建议取值 | 说明 |
| --- | --- | --- |
| 完整性 | complete / incomplete / unknown | 用户是否表达完；与控制命令分开 |
| 交互意图 | answer / correction / new_request / backchannel / unknown | 区分短回答、纠正、请求和附和 |
| 控制意图 | none / stop_response / pause / resume / end_session / unknown | 停当前回答、暂停、恢复、结束会话分别处理 |
| 输入有效性 | meaningful / nonsemantic / unknown | 不能凭文本猜测说话人或把所有笑声、哭声都当噪声 |
| 判断状态 | ok / abstained / timeout / unavailable / invalid_output | 模型运行状态；与语义结果分开 |

每个有效维度可附置信度；模型完整性概率与通用 confidence 分别命名。原始分数没有经过校准时不应跨模型复用同一个阈值。运行时继续负责 generation/revision 过期检查，并产生实际动作：继续、暂时停播、取消旧回答、提交新轮次、等待恢复、忽略输入或恢复播放。

`end_session` 只用于明确结束通话意图，不能把“这个问题不用查了”直接解释成结束会话。模型的 wait 若无法区分暂停与结束，适配器应保留未知子类型，交给策略处理。暂停需要定义恢复触发、用户指定等待时长和超时策略；仅增加标签不会自动完成状态管理。

兼容路径：保留当前 v1 结果；新结果使用明确版本与适配器。对普通完整性模型继续映射 complete/incomplete，对 invalid/wait 不做有损映射后就假定行为等价。音频模型还需补充采样率、当前轮范围、时间戳、片段生命周期和可选声学观察；当前文本合约不能直接完成接入。

## 最小验收场景

| 场景 | 期望行为 |
| --- | --- |
| “我想订一张从北京到……” | 等待补全，避免抢答 |
| 助手问“是质量问题吗？”，用户“嗯” | 有效回答，不能仅凭附和词丢弃 |
| 助手解释过程中用户“嗯嗯，继续” | 通常继续播放，结合上下文确认 |
| “等我十秒，我找一下订单号” | 暂停交互，按明确策略恢复，不走普通 incomplete 超时回复 |
| “别说了” | 停当前回答，不自动结束整个会话 |
| “别说了，改成查上海” | 停旧回答，保留并提交新请求 |
| “不是北京，是上海” | 纠正并接管话轮，保留最终文本 |
| “对……不对，我重新说” | 支持修订与自我纠正，旧判断不能覆盖新文本 |
| 咳嗽、背景电视、助手回声 | 使用对应音频/回声证据评测，不能声称文本分类已解决 |
| 模型超时、非法输出、旧 revision 晚返回 | 明确降级原因；不丢用户输入，不执行过期判断 |
| 暂时停播后确认误打断 | 按策略恢复且不重复或跳过已播放内容 |

评测数据需标注历史、当前累计文本、边界、revision、播放状态及期望动作。加入有历史/无历史、ASR 错字、重叠讲话和不同静音时长；有歧义样本允许 unknown，不能强行标确定答案。

至少观察：提前判停率、延后判停率、回复延迟 p50/p95、附和误取消率、真实打断停播延迟、用户轮次丢失率、误打断恢复成功率、模型错误率与降级动作分布。采用相同录音回放、时序与硬件比较插件；不能只测离线标签准确率。

## 推荐落地顺序

1. 先建立上述场景集，补齐结果与动作的日志，独立记录故障来源；核查短回答与多意图输入。
2. 增量扩展结构化结果，完成 invalid/wait 的明确适配与暂停/恢复策略，保留旧插件兼容层。
3. 增加音频输入合约，以统一回放评测选择文本、声学或融合模型，再调校阈值。

后续已通过 TypeSafe 官网核实 [Jev 的类型化决策接口](https://docs.typesafe.ai/introduction)。输入归属、连续判停/打断及协调器规划见文档页面《语音交互审查与框架规划》（`voice-interaction-review`）。现有接口已允许当前轮文本、可选历史与输入状态；新增输出维度和暂停生命周期仍属于待实施优化。
