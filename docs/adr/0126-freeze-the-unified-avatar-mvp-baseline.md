# Freeze the unified Avatar MVP baseline

The MVP includes one immutable-image Avatar aggregate with optional accepted Anam realtime binding and zero-or-more accepted actions; canonical `/avatars` management, creation, detail, scoped action creation, and trash routes; separate asset management and Avatar Studio surfaces on the shared home visual shell; existing-image, upload, and seamlessly delegated HappyImage generation sources; explicit Anam creation and preview acceptance; template-first LivePortrait action creation and acceptance; required Lip-sync Model preparation plus one-source/one-model session-start preparation; private and built-in library scopes; durable task recovery; home Session Configuration Workbench launch handoff; 30-day Avatar and action recovery; and direct legacy naming migration that preserves resolvable ID values and deletes reported orphans. The MVP excludes image quality, face, safety, and compatibility gates; Avatar-processing billing; single-frame pose editing; automatic action creation, semantic switching, or multiple action bindings per session; Provider selection beyond Anam; HappyImage iframe or shared-Cookie integration; and legacy API, field, type, component, or route compatibility layers.
