# Delegate HappyImage identity without a browser authorization flow

Avatar Studio calls HappyImage without a redirect, popup, iframe, or second credential prompt. After authenticating the user in OpenRealtime, its server sends HappyImage a short-lived signed assertion containing the verified Casdoor `sub`, intended audience, minimum task/result scopes, expiry, and replay-resistant identifier; HappyImage accepts assertions only from the registered OpenRealtime service, maps the subject to the correct quota owner, and automatically provisions the corresponding HappyImage user record on first use. HappyImage must add this trusted internal API because its existing independent browser session cannot safely provide this seamless integration by itself. We explicitly reject sharing a Cookie domain, signing key, session store, or forwarded browser Cookie as either the primary path or a temporary fallback: that shortcut couples deployment and expands either application's session compromise into the other.
