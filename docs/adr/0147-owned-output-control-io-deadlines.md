# ADR 0147：停播控制 IO 的等待截止与退出归属

日期：2026-10-07。状态：Accepted，限异步 Transport 控制 IO；完整G4仍开放。

## 问题

ADR0146的恢复通知使用asyncio.timeout，停播命令和故障关闭使用wait_for。适配器吞掉CancelledError时，这些等待会继续阻塞；原计划截止已过，但调用者不能推进到失败出口。仅设置取消或写一个deadline配置不证明IO真实退出。

## 决策

在既有RealtimeWebSocketFrameBridge内复用一个私有控制IO等待方法，不增加业务状态机、输出队列或存储。方法创建并登记IO任务，以asyncio.wait限制调用者等待。截止或调用者取消只发送cancel请求；任务仍占据现有Bridge的pending集合，真实退出后才由done callback移除。回调读取并记录迟到异常，任务名带Voice Session ID，避免无人接收的异常与无来源诊断。

每个Bridge最多8个未退出控制IO任务；超过预算拒绝新操作并关闭未启动的coroutine。异常由现有失败出口处理，不能把资源预算失败解释为停播成功。残留任务计入预算，不因关闭或取消就释放名额。

覆盖恢复epoch通知、精确停播命令、兼容/目标缺失停播命令、失败通知和Transport.close。恢复通知仍使用原剩余恢复截止与停播IO预算的较小值，完成后继续重核原截止、附着和交付权限。停播失败同步封锁PCM；通知和关闭的等待各有限时，最终无论适配器是否实际退出都唤醒Endpoint失败观察，允许本地Brain/TTS/classifier清理。

正常begin_close先声明关闭并取消控制IO。随后的发送截止或异常不再新发故障；原stop的session_closed原因保留。close等待通知任务、控制IO及原持久事实写入各有有限预算；仍未退出的任务继续归属原Bridge，留下残留诊断，不假报已完成清理。

## 保证与限制

保证异步不合作awaitable不能无限延长调用者等待、不能在失败后打开新PCM交付权限，也不能让关闭忘记任务归属。已进入适配器的send不能强制撤回，适配器的真实退出与调用者返回分别报告。本方法不能抢占阻塞整个Python事件循环的CPU代码，也不能强制终止永久吞取消的插件。

持久RecordOutputStop和播放投影仍使用各自原任务归属，本ADR不声称覆盖它们或全部供应商等待。完整真实供应商、断连、数字人renderer及资源负载矩阵仍按G4/G5验收。

## 验证

非合作恢复通知的普通/正式Endpoint两例先红；改为独立有界等待后绿。兼容停播的旧wait_for路径随后独立复现并统一迁移。正常关闭不取消调用者、适配器仍吞取消的四种竞争先红后绿。新增14个正式回归覆盖晚成功/晚异常、精确/兼容停止、正常关闭及实际Endpoint故障退出；本地会话资源释放后，残留IO到真实退出才从归属集合移除。
