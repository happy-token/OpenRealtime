# Use native Avatar image creation over the HappyImage API

Avatar creation uses an OpenRealtime-native page and focused UI extracted from HappyImage while HappyImage remains authoritative for generation entitlement, billing-backed quota, image tasks, and its own private generated media. We rejected embedding the complete HappyImage application because its current frame policy forbids framing and an iframe would make authentication and secure result handoff fragile; we also rejected copying the whole product frontend because its history, gallery, provider settings, and account state are outside Avatar Studio. A generated image becomes an Avatar only after an explicit named save imports an immutable source copy into the Avatar asset boundary; the saved Avatar does not retain a runtime dependency on the HappyImage result URL or lifecycle.
