# ADR 0156: Authorized Session preservation and optional catalog state

Date: 2026-10-07
Status: Accepted for local implementation; production deployment and full recording acceptance remain open.

## Decision

Expose the existing Runtime preservation operation through an administrator-only public POST and a signed private transport. Public requests require a current application administrator and an exact same-origin Origin against the actual HTTP Host. Next can normalize a loopback URL to localhost, so the wire Host takes precedence when present; malformed Host never falls back, and Forwarded/Referer cannot authorize a write. Any Authorization header is rejected before Cookie authorization, including a valid Session Agent read grant. The browser supplies neither actor nor source identity, query parameters nor a request body.

After the admin check, Next hashes issuer/subject into an opaque actor and signs the Session, exact raw body and timestamp. Derive a private HMAC key from the existing 32-byte `VOICEAGENT_CREDENTIAL_ENCRYPTION_KEY` with a distinct preservation domain. Python requires the same configured root and a valid proof within 60 seconds, constant-time signature comparison and loopback Host/optional Origin. Missing/mismatched configuration fails closed. Proofs, root keys, Cookies and Bearer credentials are not published or forwarded together. The proof authenticates the trusted admin gateway; private loopback reachability alone is insufficient. Replaying an identical proof can only repeat the same monotonic, idempotent mark, not change the Session or unmark it.

Catalog state is a separate whitelisted projection: preserved/unmarked/source-missing/unsupported/unavailable, first mark time, verified/pending/unavailable counts and storage durability. No original owner or actor is published. Optional state failure must not hide independently verified recording rows. ApplicationRecordingOwner gives this query at most 250ms inside the original catalog deadline and uses the same eight actual operation slots. On timeout the page returns unavailable; the actual policy task retains its slot, purge/close protection and exception settlement callback until completion. At capacity, or without an owner, optional IO is not started. No detached task, extra queue or actor is added.

The existing themed recording panel adds a Session-wide preservation button. It is enabled only after a verified unmarked catalog. Duplicate clicks share one request. A confirmed mark triggers an actual catalog refresh; row pinning is never fabricated from the POST response. A timeout is explicitly unconfirmed and requires catalog refresh before another mark. A confirmed mark with failed refresh stays confirmed while identifying stale rows. Leaving the page fences late results. Volatile storage explicitly does not survive restart; pending counts do not prove uploads completed. Seven-day retention, original-source policy and deletion protection remain ADR0154–0155 responsibilities.

## Verification and limits

Formal red/green tests cover a hanging optional getter and Next's loopback URL normalization. Signed real HTTP tests reject missing/tampered/foreign/stale proof, Agent headers and hostile Host/Origin before mutation. Controlled UI tests cover duplicate, uncertainty, refresh and late results. Isolated Chrome uses actual PostgreSQL administrator identity, Memory Runtime recording/Journal/Artifact, real private HTTP and Next routes, WAV Range playback, refreshed preservation and Cookie-free Agent reads. Fixture input is synthetic validated PCM; this proves browser media decoding/completion, not original-session renderer confirmation or a user actually hearing it. The opt-in spec needs an explicitly started owned fixture; ordinary E2E does not start it.

No new production migration, root key, running-service restart or S3/provider call is performed. Deployment still requires controlled 0035–0038 migration and coordinated services with the existing shared private root. Real S3, recording completeness, confirmed epoch/speech/sample joins, external Agent deployment, OBS02/OBS03 and all original G0–G5 gates remain open.
