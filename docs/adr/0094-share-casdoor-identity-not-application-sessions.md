# Share Casdoor identity, not application sessions

OpenRealtime and HappyImage trust the same Casdoor subject as the stable user identity, allowing OpenRealtime to record Avatar ownership and HappyImage to apply that user's generation entitlement and quota, but each application retains its own browser-session boundary. Avatar Studio does not open a HappyImage login or authorization flow: OpenRealtime verifies its user, signs a short-lived audience-bound assertion with the Casdoor subject and minimum generation/result scopes, and calls a HappyImage internal endpoint that trusts only the registered OpenRealtime service. HappyImage maps or just-in-time provisions its user/quota record from that subject. The browser never copies HappyImage cookies, API keys, or quota tokens into OpenRealtime, and the applications never share a Cookie domain, signing secret, session store, or forwarded browser session as a shortcut.
