# Copy saved images into Avatar-owned storage

When a user saves a HappyImage result as an Avatar, OpenRealtime obtains the selected image through an authorized server-to-server integration and writes an immutable master to private Avatar-owned object storage before atomically creating the `avatar_id` record. The Avatar records provenance such as HappyImage task and result identifiers, source hash, and owner, but never relies on a browser-supplied remote URL, a public object URL, or HappyImage retention and signed-URL lifetime. The MVP adds no product-level face, image-quality, compatibility, or safety-check gate before save; ordinary transport and object-storage limits remain infrastructure behavior rather than a new user flow. Avatar and HappyImage deletion remain independent: removing either product's record does not silently remove the other's source object.
