# Use one Device Audio Input Runtime with an AudioWorklet Web conformer

Every client presents microphone audio to Voice Session Runtime through one Device Audio Input Runtime behavioral boundary. It owns the device capture graph, negotiated format conversion, framing, monotonic capture timestamps and sequence, `input_epoch`, bounded prebuffering, `release/reset/mute`, and capture-health telemetry before Audio Frames cross the transport boundary.

Desktop Web implements this boundary with `getUserMedia`, Web Audio, and an AudioWorklet-centered conformer. AudioWorklet keeps timing-sensitive PCM work off the UI main thread and implements a bounded `buffering → replaying → live` state machine with leading-silence trimming and short pre-roll. Native and embedded clients use their platform audio primitives but preserve the same epoch, ordering, release, reset, overflow, and observability behavior; AudioWorklet is not a server or cross-platform protocol type.

The initial versioned Device Capture Profile uses the locally observed GPT Voice startup baseline: a 30-second maximum ring buffer, `0.003` leading-silence energy threshold, 100ms pre-roll, and 32ms output Audio Frames. These values are profile defaults rather than wire-protocol constants. First-word loss, false release, overflow, device/browser override, and recovery-latency telemetry may justify a later profile version; runtime records always identify the requested and effective profile.

Capture enhancement is device-first and has exactly one effective owner per effect. Desktop Web requests platform echo cancellation, noise suppression, and automatic gain control through `getUserMedia` and reports the browser's effective constraints. The initial AudioWorklet conformer does not duplicate heavyweight DSP. Phase 1 has no server AEC because the WebSocket server lacks a sufficiently aligned playback-reference signal; the server Audio Graph may add noise suppression or gain processing only when the client explicitly reports that effect absent and policy requires it. Device replacement or capture-graph rebuild renegotiates and reports the effective profile.

Every microphone replacement or capture-graph rebuild creates a new `input_epoch`. The old Worklet state is reset and no prior-epoch PCM is joined to the new device stream. If reconfiguration intersects user speech, that input is settled as `aborted_by_device_change`, not assembled into a cross-device Turn. Because the network and server session remain healthy, Voice Session Phase stays `ACTIVE`; only input admission closes until the new effective profile is known and an epoch-specific release succeeds. Assistant output and durable Agent Tasks continue independently while the client exposes the temporary capture state.

The wire contract opens each capture timeline with `InputEpochStarted`, carrying the epoch identity, requested/effective Device Capture Profile, immutable `format_id`, and timeline origin. Each `InputAudioFrame` then carries `input_epoch`, monotonic `sequence`, relative `start_sample`, `sample_count`, `capture_mode` (`prebuffer` or `live`), and encoded payload. The authorized Endpoint connection already binds Voice Session identity, so ordinary frames do not repeat it.

The server periodically returns `InputAudioAck` with the highest contiguous admitted sequence rather than acknowledging every 32ms frame. Duplicate sequences are idempotently ignored; a closed or mismatched epoch is rejected; discontinuous sample position becomes an explicit Audio Gap; and any effective format change requires a new epoch. The unsequenced `audio_chunk` frame remains only as a migration adapter and is removed with Legacy Runtime Path.

Endpoint protocol version is selected once through `SessionHello.supported_protocol_versions` and `SessionAck.protocol_version`. v2 accepts only the epoch-aware input family and never infers or downgrades version from an individual frame. Legacy v1 `audio_chunk` is isolated in an explicit compatibility adapter disabled by default in production; no common version returns a structured upgrade-required close. After Desktop Web v2 contract, reconnect, and E2E gates pass, the v1 adapter is deleted with Legacy Runtime Path. ESP32 later implements v2 directly and does not block removal.

Prebuffered and concurrently captured PCM remain on one ordered sample timeline during release. Unlike the clean-room reference Worklet, the production conformer does not silently discard voiced input captured while older samples replay. When downstream capability declares accelerated ingestion, the Phase 1 WebSocket profile drains at a bounded maximum `2x`, paced by `InputAudioAck` and send-queue watermarks rather than one burst; confirmed silence may be skipped, but voiced samples may not. It enters `live` only after reaching the capture boundary.

`max_replay_rate`, catch-up deadline, and queue watermarks are Device Capture Profile fields. If accelerated ingest is unsupported or the queue cannot catch up within its capacity/deadline, the client resets the epoch, reports explicit overflow/Audio Gap evidence, and asks the user to repeat rather than sending a truncated utterance. `2x` is an initial WebSocket value subject to provider ASR/Native Engine conformance tests, not a cross-transport constant.

Raw prebuffer PCM exists only in AudioWorklet/page-process memory. It is not written to IndexedDB, LocalStorage, files, application logs, or default crash reports, and it does not leave the device before an epoch-matching release. Reset, session close, permission revocation, hidden-page timeout, device replacement, and epoch termination clear the ring and overwrite reusable storage. Ordinary telemetry contains only duration/capacity, aggregate energy, overflow/drop/gap, and state transitions.

Raw-audio diagnostics are a separate, default-off capability requiring explicit time-bounded authorization, retention/deletion policy, and access audit. The client displays active microphone capture throughout buffering, replaying, and live states; local buffering is not represented to the user as absence of recording.

There is no cross-tab Device Media Lease keyed by `device_id`. Each tab may independently request browser capture permission, construct a Device Audio Input Runtime, and run a Voice Session. Browser/OS device-sharing behavior is surfaced as effective capability or capture failure; the server does not reject an input epoch merely because another Voice Session on the same device is active.

The server remains authoritative for Voice Session Phase. A new client `input_epoch` buffers during `STARTING` or `RECONNECTING`; only a barrier-complete release correlated to that epoch may expose its frames to Turn/Engine. Disconnect, session replacement, recovery timeout, explicit stop, or overflow resets the affected epoch. Old network frames, output media, and prior-epoch microphone PCM are never replayed, so this startup/first-word protection is compatible with ADR-0068 Semantic Session Resume.

Local energy measurement may trim leading silence, retain pre-roll, drive UI, and report diagnostics, but it does not become authoritative VAD, endpointing, ASR, speaker identity, or Barge-in classification. Device Audio Input Runtime also does not own transport retry, model/session recovery, or application authorization.

The existing Web path posts fixed 32ms PCM buffers to the main thread and drops them whenever WebSocket is not open. Migration adds explicit Worklet control messages and state, bounded ring storage, epoch-tagged release/reset, and input Audio Frame metadata without retaining a second microphone-send path. Tests must cover first-word preservation, strict ordering through replay-to-live, concurrent speech during replay, paced `2x` catch-up, downstream no-acceleration fallback, stale release rejection, epoch reset, 30-second overflow, reconnect, device change, AudioContext suspension, Worklet failure, lifecycle buffer clearing, absence of raw PCM in persistence/logging, and explicit diagnostic authorization.
