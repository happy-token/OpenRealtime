# Replace Anam bindings only after a new preview is accepted

`效果不满意，重新创建` submits another Anam Avatar task from the same immutable Avatar Source Image and product `avatar_id`, producing a candidate Provider Avatar ID rather than a second product Avatar. The MVP permits at most one accepted Anam binding per Avatar: an existing accepted binding remains selectable while the replacement is created and reviewed, then acceptance atomically makes the new binding authoritative for future sessions and moves the old ID into provider-attempt history. Failed, rejected, and superseded IDs never appear as independent Avatar cards or home-workbench choices. When the provider lacks a confirmed remote-delete API, OpenRealtime unlinks the attempt and records cleanup debt instead of claiming the remote resource was deleted.
