# Preserve legacy ID values while renaming Avatar fields

Resolved legacy assets keep their identifier values during the unified Avatar migration: the value formerly stored as `visual_identity_id` becomes `avatar_id`, and the value formerly stored as `motion_base_id` becomes `avatar_action_id`. Database renames or same-value backfills are preferred over generating replacement identifiers, preserving old session references, object paths, accepted media, and Renderer assets without a remapping table. The cutover is immediate rather than compatibility-based: every post-migration type, route, API request and response, database field, test, and internal call uses `avatar_id`, `avatar_action_id`, `provider_avatar_id`, or `renderer_asset_id`; no deprecated read/write aliases remain.
