# Create Anam realtime bindings in Avatar Studio

Avatar Studio includes an optional `实时驱动（Anam）` stage after the source image and before optional repeatable actions. Because Anam is the only MVP provider, no one-item provider selector is rendered. OpenRealtime sends the private source image to Anam's `POST /v1/avatars` multipart endpoint with the display name and an organization-available Avatar model, stores the returned Anam ID as `provider_avatar_id`, and keeps creation plus preview state durable across navigation. A single available model is selected without another control; multiple authorized models expose a selector with the recommended version preselected. This follows Anam's official [Create Avatar API](https://anam.ai/docs/api-reference/avatars/create-avatar) and [custom Avatar guide](https://anam.ai/docs/personas/avatars/custom-avatars). After creation, preview polling continues durably and the binding remains unavailable for session selection until the preview appears and the user clicks `确认实时驱动效果`; the command itself is acceptance and needs no checkbox. Users may skip or retry the stage without affecting image or segmented capabilities, and an Avatar detail can reopen it later; the home Session Configuration Workbench only consumes an accepted provider binding. ADR-0116 is superseded.
