# 语音交互与会话诊断：统一需求基线

复核日期：2026-10-06。本文整合已确认的产品要求；运行状态细则见[纠正与恢复需求](2026-10-05-voice-interaction-correction.md)。实施状态和性能结论分别以[实施计划](../design/2026-10-05-voice-correction-implementation-plan.md)、[实验计划](../design/2026-10-06-voice-interaction-experiment-plan.md)为准。

## 1. 目标与优先级

第一优先级是正确交互：有意义的表达与补充不丢失，附和和噪声不抢话，旧任务不污染新回复，异常后有明确出口。第二优先级是缩短真实响应和打断延迟，并能解释长尾来源。诊断必须支持管理员或授权 Agent 仅凭 Session ID 还原全过程。

Token 用量和费用是辅助信息。不能通过减少有效输入、把失败样本排除或取消必要的播放确认来获得好看的延迟。

## 3. 用户场景与最终结果

|场景|期望行为|
|---|---|
|完整表达后正常结束|当前累计语义完整且满足声学停止条件，提交一次；允许提前准备回复|
|一句内停顿或仍在补充|保持输入；旧前缀完整不能提交更新后的文本；截止后有界复核或澄清|
|“推荐北京酒店……是上海，带孩子”|将重要补充关联原问题；未播重做；一般补充句末衔接；正在播错误地点时立即纠正|
|“嗯、对、好的”与背景声|根据上下文区分反馈、提问回答与噪声；不因保留输入而隐式停播|
|“停”“不是”“上海”|短停止/短纠正可生效，不能用五字封口阈值过滤有意义的内容|
|并行结果前后不一致|判停用有效累计输入版本；打断用仍有效的目标与证据；旧结果不能回滚当前状态|
|打断后 ASR 改写证明是附和|确认这是新证据，创建恢复版本；检查实际停播和已播位置|
|旧输出自然结束，用户输入仍不确定|输出完成不等于输入失效；重新归属并有界处理，禁止静默丢弃有意义文本|
|断连、回执丢失或模型失败|保留证据与输入；未知状态不能伪装成功；恢复/澄清/明确失败，禁止新旧声音重叠|
|管理员定位“后面一直没响应”|Session 时间线指出卡在哪个等待、其截止与最终出口；缺数据也可见|

## 4. 延迟与异常口径

|展示名称|测量边界/限制|
|---|---|
|ASR 建立连接|开始建连到提供商初始化就绪；握手/发送配置与提供商确认须注明；初建与异常重连分开|
|ASR 首包延迟|本轮有效语音开始到首个非空文本；不是会话建立到首文本|
|ASR 尾包延迟|本轮最后有效语音结束到最终文本确定；缺任一边界显示未知，不用 0 补齐|
|语义判停 / 打断|分封口等待、候选排队、共享槽位、客户端准备、SDK 请求、解析与结果裁决；调用全程不是整体交互延迟|
|LLM 首文本延迟|请求开始到首个可用文本；预生成命中后提交等待另列；不把缓存等待当模型 TTFT|
|TTS 建立连接 / 首包延迟|初建/预连接/复用/重连分组；首包明确从首文本或文本提交开始，不混用边界|
|交互响应延迟|最后有效语音结束到对应回复实际开始播放；估算和客户端测量分别统计|
|有效打断延迟|被确认的有效打断语音开始到目标旧输出实际停止；挂断/自然结束另列|
|纠正衔接延迟|补充说完到修正回复首播，单列当前句剩余播放等待；不混入普通回复|
|失败 / 超时 / 取消|按操作 ID 和事件因果关联；正常版本替换取消单列，不能算故障，也不能隐藏其资源消耗|
|断连 / 恢复|按连接 attempt ID 计数，排除正常关闭；恢复成功率使用有终态的恢复尝试作分母，待恢复另列|

总体卡片使用 P50/P95/N；实验报告另给平均值。低样本、锚点缺失、日志丢失、历史未采集都显示完整度。不同测量边界不合并成一个分布，各模块可能重叠，不能相加代表端到端。

评估 ASR/TTS 预连接、连接复用与冷暖链路收益；记录实际 provider/model/config，而不是仅写“JEV”。SDK 请求包括传输、服务处理和解析，不能当成纯模型推理；初建就绪的耗时也不能替代后续首包耗时。renderer 回执证明其播放状态，不能证明已经录到物理扬声器或用户实际听见。

## 5. 统一证据接口的最低契约

现有入口：`GET /api/observability/sessions/{sessionId}/diagnostics`，使用应用管理员认证。目标契约扩展现有接口，不再另建一套日志数据源：

- 返回会话、逻辑输入/回复身份、原始 ASR 修订与封口候选、分类结果与有效性原因、生成/交付/播放事实、异常及截止出口。
- 标明 schema 版本、数据来源、分页/截断、采集健康及缺失项；Agent 不能把“没返回”解释成“没发生”。
- 提供录音/音频证据引用及时间轴映射；录制失败和过期可查询。
- 呈现 generated、sent、confirmed_played 三类事实，未知部分保留未知。
- 机器调用需要独立受限的只读身份与访问范围；浏览器 Cookie 不是已经完成的机器授权方案。管理员 Session 链接也不能绕过服务端权限。

## 6. 模块与复杂度约束

`InputPipeline → ChunkScheduler → TaskRegistry/classifier_execution → 分类插件 → Turn actor → 现有 Prefetch/Brain/TTS → 客户端输出`。

Turn actor 是唯一业务事件裁决入口。计划新增的 ReplyRevisionController 只接受 actor 命令，保存版本/替代/许可事实，并提供纯验证或规划函数；它不自行判定语义、不运行第二个状态 actor、不直接控制播放。播放边界执行 actor 签发的许可并上报事实。

需要纠正的例外必须显式表达：旧回复被替代后禁止新交付；一般补充只允许被冻结的“当前实际播放句”继续至句末，许可精确到输出 epoch 和句段，不允许旧版本任意续播。明确否定、主动结束或超时可以撤销该许可。

## 7. 本次复核后的交付顺序

1. 先建立统一测试证据、并发 1/2 相同语义契约，核查实际播放协议；补现有无响应路径的回归。
2. 实现输入/回复版本与未播纠正，保留所有输入证据并确定有界出口。
3. 建立真实停播/句末回执与选择性输出许可，再实现句末衔接及即时纠正。
4. 在可靠播放事实之上实现误打断恢复。
5. 每阶段执行正确性、故障和真实录音实验，最后做综合灰度；延迟结论必须来自可比较的实验。
